# 风格第四批：解析覆盖不完整的文件

日期：2026-11-17。基准为 HEAD `3e02e0f` 加此前未提交的 S1–S4 和三批风格修改。
接续[小数写法整理](style_decimal_2026-11-17.md)，本批处理剩余引号、END 命名、小数写法。

## 解析问题与处理范围

Fortitude 原始扫描报 E001 的 20 份文件分为：

- 15 份含跨行拆开的 FORMAT 描述符：七份 `strsum`、四份 `solve`、三份 `spme` 和 `setcon`；
- 三份 `sixj1/sixj3/sixj35` 的算术表达式续行；
- `ci_damping.F90` 和 `cache_io.F90` 的条件预处理分支。

按 CMake compile commands 中的实际宏配置预处理这 20 份文件，共 27 个编译上下文；
在仅用于诊断的副本中合并物理续行后，Fortitude E001、S241、S061、S291 全部为零。
生产文件的续行和测试条件分支没有为迎合分析器而删除，原始扫描仍有 20 条 E001。
临时副本的扫描只用于定位分析器覆盖限制，实际源码由完整编译和回归验证。

逐字符检查完整文件，保留解码后的字符串内容，处理了 18 份文件：

- 731 处单引号字符串改为双引号，包含解析器未报告的字符串；
- 16 处小数补零，原 kind、指数和数值不变；
- `ci_damping.F90` 的八个程序单元结尾补名称。`maneig`/`maneigmpi` 使用与声明一致的
  `CI_MPI` 条件分支，分别结束对应子程序。

另纳入此前剩余的 `radgrd.f90` 两处含转义单引号的 FORMAT 字符串，转换时保留实际单引号字符。
字符串外只有指定小数补零和 END 命名修改；不改注释内容、计算表达式或数值类型。
生产源码物理行数不变，测试文件因条件 END 增加四行，没有新增超长行。
三份 sixj 文件没有这三类风格问题，检查后保持原样。

八份导入 RMCDHF 文件追加
[parser-style 快照](../reference/rmcdhf_parser_style_snapshot.json)，绑定 decimal manifest；
所有历史快照保持原样，来源检查继续验证精确哈希。

## 验证

使用本机 Homebrew GNU Fortran 15.3.0，显式指定 FC/OMPI_FC；仓库服务器工具链约定不变。
使用共享 Python 环境和独立 Release/Check 构建目录。

- 原始全量 Fortitude 扫描的 S241、S061、S291 均归零；默认诊断从 10,911 降至 10,433。
  消除原报告的 478 条提示，并处理报告范围外的 273 处字符串和四个 END。
- correctness/portability/obsolescent/error 加 preview 仍为 16,377 条，按文件、规则和消息
  多重集合比较完全一致；条件 END 增加行数使部分测试文件诊断位置后移。
- 三对不同小数写法的 KIND 和 TRANSFER 字节位模式逐对一致。
- RADGRD FORMAT 300 用修改前后原文分别编译、运行，完整输出逐字节一致，包括单引号字符。
- Release/Check 全量构建通过，两套 CTest 均一次性 89/89 通过。
- 22 个受影响 Release 编译对象中，两个逐字节一致，15 个仅在 `__const` 区改变引号字节，
  其中 132 处格式文本解码后一致。RADGRD 的反汇编只有 FORMAT 原文长度从 101 改为 99，
  对应两个转义单引号各减少一个源字符，输出已作独立字节对照。
  四个 CI 测试对象的反汇编一致，字符串差异仅为新增条件 END 导致的诊断行号后移四行。
- 492 份导入文件来源检查通过，源码和历史快照篡改负例全部被拒绝；`git diff --check` 通过。
