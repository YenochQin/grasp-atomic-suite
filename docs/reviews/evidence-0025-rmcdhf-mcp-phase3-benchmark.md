XFS/NVMe 上完成了作业 14 的全 SCF 对照和作业 15 的势系数分段对照。两次均观察到

## 两套基准的代码边界

- 路径 A 保留按 rank、按通道写出的旧 MCP 和逐轨道扫描。路径 C 每 rank 写一个带块和组目录的
  `mcp.mcpidx`，有选根的块按目录定位。普通 MPI 版在每次 EOL 密度权重更新后重建收缩表，
  轨道和乘子复用组收缩。MPI 内存版读取同一格式。dev 的计算入口使用目录格式单路径。
  [实现和阶段 0–2 验证](../implemented/design-0020-rmcdhf-mcp-io.md)
- 代表性多块算例对照采用同一份 V3 描述符和输入，由各自的 `rangular_mpi` 重新生成 MCP，
  各自的 `rmcdhf_mpi` 求解。阶段 3 测量代码在两个独立的源码快照中编译。
  快照生成器以 Git 提交为输入，记录提交、探针和注入脚本的 SHA-256。
- 作业 14 的探针覆盖 `run_scf_iterations_mpi` 全段。后续测试包保留全段数据，
  增加势系数构造与已有 MPI 集合调用的分段计时。两份基准都采用相同采样边界和探针源文件。

## 作业 14 的生产对照

Zn I AS2 含 4 个对称块，每块分别有 6,365、17,701、25,897、29,534 个 CSF，共 79,497 个。
同一 Linux 节点使用 48 个 ranks，Slurm 按核绑定。归档版和 dev 使用相同的描述符、初始波函数、
核数据、交互输入及 MPI/BLAS 动态库。SCF 上限为三轮。冷、热缓存各做三次配对对照，
相邻重复交换 old 和 dev 的运行顺序。每次启动 RMCDHF 前用 `mincore` 核对 MCP 文件页，
冷态均不驻留，热态均驻留。

涵盖各 rank 从启动到采样点的内存峰值。最慢 rank 墙钟是每次运行中 rank 的最大本地 SCF 耗时。

热态每轮节省 26.58–32.27 秒。C 在六次 SCF 中的最大单 rank RSS 为 569.64 MiB。

两版的 12 次运行具有相同的迭代号、输出能量、停止状态以及 `.mix`、`.wfn` 的 SHA-256。
各次均到达设置的三轮迭代上限。初始和三轮加权平均能量分别为
−1794.5696497、−1794.6448855、−1794.7740417、−1794.7829098 Hartree。

MCP 每版生成一次。A 用 22.62 秒生成 576 个分片、4,272,972,236 字节，

生成只测了一次，临时文件的磁盘峰值和重复生成成本待测。

### 作业 14 的验收判断

- **SCF 数值一致，墙钟可重复下降。** 冷、热态的全部六组配对都加速。
  热缓存时两版的 SCF 实际读盘均为零，仍观察到加速。逻辑扫描、收缩计算与 MPI 等待
  对加速的各自贡献需要分段计量。
- **势系数实际读盘条件待证。** 冷态全 SCF 读量增加。全 SCF 读量包含矩阵装配和势系数阶段。
  在势系数构造前，矩阵装配可能已经把相应 MCP 页读入缓存。要判断计划中的势系数物理
  读取是否下降，需要独立采样这一段。生产 `--mcp-trace` 的逻辑读取字节用于解释扫描和跳过，
  与 Linux `read_bytes` 的存储读取归因分开比较。
- **内存预算、B 对照和生成峰值待核。** 用 C 的 569.64 MiB 最大 rank 峰值与目标预算核对。
  作业 14 测了 A/C。若要拆分收缩复用与磁盘格式的增量，需在同一文件系统补测归档 B。
  串行与 MPI 内存版的性能验收各自使用匹配基线。

## 势系数补测的实现和验证

| 指标 | 探针窗口和汇总 |
| --- | --- |
| 势系数实际读盘与墙钟 | 包住每次 `assemble_orbital_potential_coefficients`。覆盖普通、追加和重试轨道更新及 Lagrange 乘子的两侧。每 rank 累加 `read_bytes` 差值和 `MPI_Wtime`。 |
| 最慢势系数 rank | 取上述累计构造墙钟的最大值，同时记录该 rank 的读量及 MPI 调用耗时。 |
| MPI 等待与通信 | 分别计径向势 `MPI_Allreduce`、乘子 `MPI_Allreduce` 和直接系数汇集的 `MPI_Gather`／`MPI_Bcast`。累计阻塞调用时间包含通信、归约和等候。集合调用沿用求解器原次序。 |
| 全 SCF 对照 | 保留全 SCF 读盘、最慢 rank 墙钟、最大 rank RSS、整次调用墙钟、缓存驻留和数值一致性检查。 |

复跑包 `stage3-potential-kit.tar.gz` 含两份带探针快照、原算例、构建及提交脚本。
每个 SCF 目录保留每 rank 的 `scf-perf.csv`，`summary.json` 保留逐轮运行与按冷、热态计算的中位数。
重点字段为 `potential_read_bytes_all_ranks`、`slowest_rank_potential_seconds`、
`potential_read_bytes_at_slowest_potential_rank`、`potential_mpi_seconds_at_slowest_potential_rank`、
`max_rank_potential_mpi_seconds` 和 `ranks[].mpi_seconds_by_stage`。
`status: passed` 表示采集完成且数值对照一致。阶段 3 性能判定仍以每轮实测差异为准。

两份 GNU Fortran 16 Release 构建和本地双 rank 小样本均通过。归档和 dev 的三类 MPI
计数一致，`.mix` 和 `.wfn` 与上一版小样本逐位一致。作业 14 的六份算例输入校验值
与补测包一致。macOS 本地验证覆盖数值与计时采集，Linux 读计数的解析用合成数据校验。

### 本机 Btrfs 的矩阵分段对照

本机复用作业 15 的六份 Zn I AS2 输入，保持三轮 SCF 上限。使用 GNU Fortran 16.2.1、
Open MPI 5.0.11 和本机 NVMe 上的 Btrfs，以 `mpiexec` 绑定 8 个物理核。两版各自生成 MCP。
矩阵窗口覆盖稀疏结构与系数读取、旧格式文件头重定位和未选根块的跳读，截止于矩阵装配完成，
后续归约和 Davidson 对角化计入 SCF 的其余阶段。首次矩阵在第一轮 SCF 迭代之前装配，其读量单独记录。

首组之后追加两组配对。第二组先运行 C，第三组先运行 A。三组采用同一输入哈希、执行文件哈希、
rank 绑定和缓存检查。追加两组前重新生成 MCP，两版各自的分片数和最终字节数与首组一致。
每次冷态运行前 MCP 页均不驻留，热态运行前均驻留。三组的最慢 rank 累计耗时中位数如下。

| 指标（秒） | 冷态 A → C | 热态 A → C |
| --- | ---: | ---: |
| 全 SCF | 240.79 → 132.22 | 235.24 → 130.35 |
| 势系数构造 | 106.41 → 6.18 | 103.93 → 5.82 |
| 矩阵装配 | 6.31 → 6.03 | 6.04 → 5.60 |

六组配对的全 SCF 墙钟缩短 44.4%–45.7%，势系数墙钟缩短 93.7%–94.6%。12 次运行均到三轮上限，
迭代能量、停止状态及 `.mix`、`.wfn` 哈希一致。A/C 的最大单 rank 峰值 RSS 分别为 286.04 / 298.02 MiB。
下表给出冷态各配对的进程 `read_bytes` 合计。

| 配对 | 势系数窗口 A → C（MiB） | 矩阵装配窗口 A → C（MiB） | 全 SCF A → C（MiB） |
| --- | ---: | ---: | ---: |
| 1 | 5,638.16 → 0.00 | 3,873.61 → 3,888.84 | 9,511.88 → 3,888.84 |
| 2 | 2,135.20 → 3,682.49 | 4,100.71 → 3,889.92 | 6,236.02 → 7,572.66 |
| 3 | 75,000.80 → 3,881.79 | 5,422.37 → 3,909.93 | 80,423.41 → 7,791.83 |

势系数与全 SCF 读量均在第 1、3 组下降，在第 2 组上升。本机读盘减量的可重复性还需验证。
三组首次矩阵装配均读取约 3.8–4.0 GiB。第三组 A 的后续矩阵还读了 1,383.91 MiB，是该组矩阵读量较高的原因。

核对各 rank 的 MCP 页驻留，并将进程 I/O 计数与设备流量对齐。

本机第二次生成用约 0.25 秒的间隔扫描各版生成目录内可见的普通文件，按 inode 汇总已分配块数。
A/C 的采样峰值分别为 5.609 / 5.607 GiB，最终 MCP 文件分别为 96 / 8 个，大小为 3.9537 / 3.9554 GiB。
这次生成耗时为 81.84 / 83.72 秒。采样口径含生成目录中的临时文件，峰值受采样间隔和 Btrfs
的空间分配影响。瞬时峰值、文件系统元数据和已解除目录链接的打开文件由此采样无法覆盖。

### MCP 页驻留诊断包

`stage3-cache-external-kit.tar.gz` 在阶段 3 的 A/C 独立构建中加入 Linux `mincore` 采样。它分别记录首次
矩阵入口、最后一个初始矩阵块装配结束、首次势系数构造入口和返回。`mcp-cache.csv` 按 rank 写出驻留页、
总页数、`read_bytes` 及实时时钟。探针只映射并查询文件，沿用原求解过程的 MPI 集合调用。`summary.json`
汇总逐 rank 数据和各采样点差值，严格的矩阵及势系数读盘窗口仍见 `scf-perf.csv`。

两套 GNU Fortran 16.2.1 Release 构建使用外部 Suite `libcsf_descriptor.a`。双 rank 小样本通过冷态、
热态和关闭采样的回归，迭代能量、停止状态和输出哈希相同。C 探针单测还确认冷态查询本身不会使被查询的
数据页进入缓存，跨映射窗口的页数正确。

本机 XFS 以 8 ranks 跑了一组 Zn I AS2 冷态诊断。启动前两版 MCP 页均不驻留，进入首个矩阵时
A/C 已分别驻留 5,173 / 1,032 页。初始矩阵的最后一块装配结束时，两版均达到全量驻留，直至首次
势系数构造返回仍为 100%。首次势系数调用和整个势系数阶段的 `read_bytes` 增量均为零。
A/C 的矩阵装配窗口分别读了 4,028.57 / 4,046.32 MiB，迭代能量和最终输出哈希与同 rank 数的
本机 XFS 性能对照一致。这组采样观察到了首个矩阵装配后的全量驻留，可解释该次势系数阶段的零读量。

### 每轮驻留与首次读盘事件

逐轮诊断包 `stage3-cache-epoch-external-kit.tar.gz` 将采样扩展到每轮 EOL 的矩阵装配和首次势系数构造
前后。该轮第一次出现正 `read_bytes` 增量时，记录各 rank 的调用序号、读量和返回后的驻留页。
如果第一次构造就发生读取，直接记录在该阶段的返回事件中。每轮结束前汇总势系数窗口内的调用次数和读量，
并与 `scf-perf.csv` 中全 SCF 的势系数窗口合计核对。三轮 SCF 有三个轨道更新阶段，末尾矩阵单列为第四轮。

逐轮版本通过两套 GNU Fortran 16.2.1 Release 构建、双 rank 冷热缓存和关闭探针的回归。输出哈希与
上一版小样本一致。受控读取测试把一个已驱逐缓存的 16 MiB 分片放在第二次势系数调用中读取，探针记录的
首次读盘序号为 2，读量为 16 MiB。

逐轮诊断随后在同一块本机 XFS 盘用 8 ranks 跑完一组 Zn I AS2 冷态对照。两版均完成三轮，每轮有
208 次势系数构造。迭代能量、停止状态和输出哈希与此前本机 XFS 的非诊断运行一致。

| 首轮采样点 | A 的 MCP 驻留页比例 | C 的 MCP 驻留页比例 |

### Rust 静态库复用

矩阵分段包 `stage3-matrix-external-kit.tar.gz` 的 `build.fish` 默认使用作业 15 已构建的
两份 Suite `libcsf_descriptor.a`，也接受两个显式 `build/lib` 目录。CMake 只导入静态库，
复用原有的平台链接依赖。缺少任一静态库时，构建脚本在配置前报错。摘要记录实际链接的静态库 SHA-256。

`c1377aa0` 自带的库可供 A 使用。C 需要新增的 `rcsfs_descriptor_basis_id`
来取得与 V3 描述符绑定的基组身份。目标平台的 `0f356733` 库可供 A、C 共用。
本地已经用同一份 dev 静态库完成两套构建和双 rank 数值对照。复现作业 14 时，
优先使用分别对应两版 Suite 的库。平台和体系结构应与测试节点匹配。
