# 保守角向复用：输出与性能对照

日期：2026-11-14。基准源码 `3f82922d2caa4de061c7f62c1b604770d0092847`，
候选为该版本加[角向缓存实现](../implemented/rangular_angular_reuse.md)的工作树。
状态：串行实现、输出回归和本机性能实验已完成；未接入 MPI/OpenMP，未运行 SCF/RCI。

## 问题、设置与判据

问题是保持普通展开 `mcp.*` 输出时，严格等价的 CSF 对能否复用角向计算，以及
查询和存储开销是否会抵消收益。预期有大量保持轨道顺序的径向同族结构时可命中；
对一般 CSF 集不预设速度收益。

Darwin arm64，GNU Fortran 15.3.0、Release `-O2`，原容量配置。基准从上述 Git
提交的归档源码独立构建，与候选使用相同编译器和编译选项。所有数学库/程序线程数
设为 1，完整相互作用，缓存 64 MiB。每个数据集三轮，每轮轮换原版文本、候选文本、
候选描述符运行顺序；输入准备、数组验证和 MCP 比较不计入进程墙钟。

判据为已有对照程序默认 `atol=rtol=0`，逐项比较贡献、重复项、稀疏结构、元数据，
再单列检查文件字节一致性。速度使用三轮墙钟中位数；缓存与阶段统计按每块记录，
进程内存使用 `wait4.ru_maxrss`。无冷缓存或 CPU 频率控制。

两组输入：

- 现有样本：14,551 CSFs、30 电子、17 轨道，四块大小 1,212 / 3,298 / 4,765 / 5,276。
  使用现有基准目录中的 `rcsf.inp` 与已经准备好的 `csfs.bin`，重新逐项验证内部数组。
- 合成样本：3,536 CSFs、闭合 `1s` 核及四个 peel 电子，n=2…15 的 s/p 轨道交错排列。
  包含四个单占 s 壳层的不同耦合链、双占与单占组合、p 子壳层项和不完整径向族。
  通过[回归样本生成器](../../test/rangular/test_reuse.py)的 `reuse_fixture(path, 14)` 生成。
  两个相邻 `0+` 块大小 3,094 / 442，第二块取第一块的子集以检查缓存生命周期；
  这是接口与性能测试数据，不作为独立原子模型。

## 结果

两组各六次候选输出均与当轮基准 **零容差相同、所有 MCP 文件字节一致**，
基准跨轮次也一致。描述符数组验证通过。输出大小不因缓存改变：
现有样本 10 个 MCP 文件共 306,386,882 字节；合成样本 6 个共 37,064,082 字节。

为隔离复用收益，下表用原版文本对候选文本：

| 数据 | 访问 CSF 对 | 缓存命中 | 命中率 | 原版整程 / s | 复用整程 / s | 原版/复用 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 现有 14,551 CSFs | 31,450,850 | 1 | 约 0% | 14.631 | 20.055 | 0.730× |
| 合成 3,536 CSFs | 4,885,868 | 4,882,566 | 99.9324% | 1.696 | 1.401 | 1.211× |

现有样本约慢 37.1%；合成样本时间减少约 17.4%。系数生成及缓冲阶段分别为
11.834 → 17.290 秒、1.276 → 0.989 秒。高命中仍只得到有限整程收益，因为
查询、轨道映射、CSF 对遍历、贡献缓冲、排序与输出都仍需执行；命中也包含零贡献对。

候选描述符整程中位数分别为 19.876 秒和 1.373 秒，均与候选文本输出字节一致。
描述符节省的读取耗时不能全部归因于角向复用。

| 数据 | 缓存分配上限 / MiB | 缓存有效存储峰值 / MiB | 原版进程 RSS / MiB | 复用进程 RSS / MiB |
| --- | ---: | ---: | ---: | ---: |
| 现有样本 | 64 | 38.763 | 1,222.484 | 1,256.844 |
| 合成样本 | 64 | 1.340 | 364.641 | 366.062 |

“有效存储”按程序统计的桶/耦合哈希和已使用条目/键/系数计算；固定数组实际分配
约 64 MiB，未写入页面不必全部驻留。RSS 包含原有系数排序缓冲、输入数组、运行库
等，因此既不能等同缓存预算，也不能把两个数直接相减当作精确的缓存分配量。

现有样本每块约保存 12.2–12.6 万条后键存储耗尽，总计 498,036 个保存条目、
30,952,813 次未命中后未保存。其极低命中率是**当前保守键、原遍历顺序和有限容量下**
的结果，不证明整个数据集中只有一个可复用对。合成样本两块共保存 3,302 个条目，
未触及容量限制。

## 回归与证据

新增五项专项测试在 Release、带运行时检查的 Check 下均通过；既有七项对照运行器
维护测试通过。Release 的相关六项 CTest 套件通过：MCP 解析、描述符输入、版本对照、
复用专项、OpenMP 回归与线程闭包审计。测试覆盖缓存耗尽回退、相邻块重置、共同轨道
关系、不同子壳层量子数和耦合、不同输入入口、LFORDR，以及无效参数/文件保护。
Check 的 MCP 解析、描述符输入、版本对照和复用专项四项 CTest 套件也全部通过。

开发初期 f3 零容差检查发现过新缓存键中 JQSA 的轴顺序错误，已修正为
`JQSA(orbital,channel,csf)`，并保留 f3 回归。上表与本节通过结果均来自修正后的版本。

本机证据保存在忽略目录 `build-angular-reuse/`：

- `audit.json`：基准提交、候选源文件 SHA-256、编译配置、验证日志身份、两组指标摘要。
- `baseline-source/`、`baseline-build/`、`release/`、`check/`：隔离的基准源码和构建。
- `benchmark-14551/summary.json`、`benchmark-synthetic/summary.json`：可执行文件和输入
  SHA-256、每轮运行、峰值 RSS、阶段计时、MCP 对照文件位置。
- 各 `trial_*` 目录：MCP、stdout/stderr、`execution.json`、`timings.csv`；候选有 `reuse.csv`。
- `synthetic-inputs/`：合成文本、描述符、header、交换二进制；原始现有输入的快照也在各报告中。

原版二进制 SHA-256 为 `f5f796bfbf423818ad04dfe86fd439484ccb77d6969c98884387abc9f11c5357`，
候选为 `668ebcb5c4e42c16fcf6a591fb2e56eb06e487295ad2336b9e6a25ee730ae602`。
运行命令和字段定义见[现行使用说明](../implemented/rangular_angular_reuse.md)。

结论是：该保守方案在实测的可复用样本上保持文件完全一致并加速，但不适合直接
默认用于所有输入，尤其本次现有样本明显变慢。后续应先统计生产数据的族结构和
不同缓存容量下的命中分布，再考虑分组调度或更广的等价类；当前实现没有消除二次
CSF 对遍历，也没有采用 CSFG 压缩文件格式。
