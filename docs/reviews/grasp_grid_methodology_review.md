## 1. 结论及证据等级

**实验方向合理，但目前不能认定方案已经完全正确，更不能认定 2990 容量或任何
候选网格已达到生产精度。** 把容量、分辨率、范围、迭代容差分开，并保存原版
基线是正确方向。主要问题不在 D1/D2/D3 的数值，而在原版代码的历史行为、
尾部截断、收敛退出和跨阶段网格一致性。

本文用三类证据区分结论：

- **确证**：直接来自指定版本源码或可复算的网格公式。
- **推断/建议**：由源码行为推出的方法学风险与实验安排，需要具体体系验证影响大小。
- **待计算**：实际能量、性质、尾部误差、最合适网格和资源成本，静态检查不能回答。

优先级最高的调整：

1. 脚本预填 `N=2990,H=.05` 已在原版径向例程中复现非有限值，不能作为通用起点。
2. `NNNP` 在尾部边界及连接点回退中参与计算，不能预设 C0/C1 一定相同。
3. P0/P1/P2 不能直接宣称是从 RMCDHF 到 RCI 的同网格点核收敛试验。
4. 成功退出不能等同于所有变分轨道达到 `SCNSTY<=ACCY`。
5. 延长 `R(N)` 不自动验证由 `MTP` 和 `ACCY` 控制的尾部误差。
6. 减半 RNT 不等于核表面网格密度加倍。

前面对话中“容量只提供存储”“约五组即可验收”等说法过于简化；
“23 个配置块检查通过”也应严格限定为配置语法和修改计划检查。
下文指出需要改正的地方，不把尚未运行的物理实验写成已通过。

## 2. 保留原版 590 基线正确，但要区分它的角色

作者手册 §1.4 明确原版默认容量为 590，扩展示例为 1990，并要求 `NNN1=NNNP+10`
及全包重编译；它不把扩容本身当成精度证明。
[作者手册](https://www.mdpi.com/2218-2004/11/4/68)

**确证：** 原版 `getscd` 有限核分支设置 `RNT=2e-6/Z, H=.05, N=NNNP`，点核分支
使用独立默认值，然后设置 `ACCY=H**6`。
[原版 getscd，第 83–99 行](https://github.com/compas/grasp/blob/9006157730a82ac839f2b4ff4e938bcba63a539e/src/appl/rmcdhf90/getscd.f90#L83)

**建议：** B0 用未经修改原版，回答“修改前后整体行为发生什么变化”。精度收敛
则应比较受控的修改组，不能要求所有细网格结果趋向 B0。原版也有离散误差和可能的
未收敛行为。C0 已改变 ACCY，B0→C0 不能充当单独的网格误差估计。

从同一干净原版提交复制各组可以减少版本混杂，但复制目录本身不是科学上的
必要条件；真正必要的是记录代码版本、补丁、实际运行参数及构建产物来源。
固定 2990 容量用于 D0–D3 是合理的工程控制，不表示把 2990 当作原版默认。

## 3. 网格公式及 D 系列：数值正确，不能机械外推收敛阶

**确证：** `RADGRD` 中 `NP10=N+10`，当 `HP=0` 时

```text
R(1)=0
R(i)=RNT [exp((i−1)H)−1]
Δr_i=(R(i)+RNT)[exp(H)−1]
```

当 `HP>0` 时解 `log(1+r/RNT)+(H/HP)r=(i−1)H`，渐近间距为 HP。
这些公式与原方案一致。
[原版 RADGRD，第 35–101 行](https://github.com/compas/grasp/blob/9006157730a82ac839f2b4ff4e938bcba63a539e/src/lib/lib9290/radgrd.f90#L35)

以下数值已用共享 Python 环境重新计算；只是网格几何值，不是物理计算结果：

| N | H | (N−1)H | Z=92、RNT=2e-6/Z 时的 R(N)，a0 |
| --- | --- | --- | --- |
| 590 | .05 | 29.45 | 134033.901814 |
| 1179 | .025 | 29.45 | 134033.901814 |
| 1965 | .015 | 29.46 | 135380.964922 |
| 2946 | .01 | 29.45 | 134033.901814 |
| 3928 | .0075 | 29.4525 | 134369.405774 |
| 2990 | .05 | 149.45 | 1.748044518e57 |

**建议：** D2 外端比 D1/D3 大约 1%，在尾部已经消失时通常不会成为主要误差；
若 MTP 靠近边界则不能忽略。当前非等比 H 序列适合观察稳定性，但不应直接套用
固定加密比的 Richardson 外推，也不能因为默认 ACCY 是 H 的六次方就声称所有
观测量具有六阶收敛。`QUAD`、原点边界、轨道优化、插值和截断共同影响最终误差。
[QUAD 的原点及尾部处理](https://github.com/compas/grasp/blob/9006157730a82ac839f2b4ff4e938bcba63a539e/src/lib/lib9290/quad.f90#L5)

## 4. 容量有实际行为：C0/C1 首次检查不可随意省略

**确证：** 原版串行 `rmcdhf90/in.f90` 设 `EPS=.01*ACCY`；循环若 `J>=N`
报错。但尾部结束条件还包含 `J==NNNP−1`，不必满足尾部小量条件也会结束。
普通 MPI 版本也有此条件；其他变体应按实际使用程序分别核查。
[IN，第 75、112、145 行](https://github.com/compas/grasp/blob/9006157730a82ac839f2b4ff4e938bcba63a539e/src/appl/rmcdhf90/in.f90#L75)

**推断：** C0 的 `NNNP=N=590` 可能在 J=589 强制结束；C1 的 `NNNP=2990,N=590`
没有同一容量边界保护，尾部未衰减时可能走到 J=590 报错。这不表示正常束缚态
必然出现差异，却足以否定“容量只能影响内存，不可能影响结果”的假设。

**建议：** 首次验证补丁时保留 C0/C1，记录 `MTP、R(MTP)、N−MTP` 及是否触及
容量边界。只有尾部自然收敛且两组数值一致，才在后续同类模型中考虑复用对照结果。
D4 如同时改容量，至少确认没有触及边界；需要严格单因素对照时补一个同网格扩容组。

**另一项条件风险确证：** `SETPOT` 找不到连接点时设置 `JP=NNNP/2`。C1 的
`NNNP=2990,N=590` 因而会选出 JP=1495，超过当前有效网格。不是每个正常解都会
触发，但应把该警告作为失败/诊断条件，不能无视后续结果。
[SETPOT，第 78–80 行](https://github.com/compas/grasp/blob/9006157730a82ac839f2b4ff4e938bcba63a539e/src/lib/lib9290/setpot.f90#L78)

因此，原方案第 5.1 节“预期在重复性容差内一致”只能是待检验假设；
第 5.6 节把 C1 作为可省略组，不适合本次首次审查旧程序扩容行为。

## 5. ACCY 扫描合理，但它控制多项数值过程

**确证：** ACCY 不只是 SCF 停止容差。`START` 用它判断近原点迭代，`IN` 用
`.01*ACCY` 决定尾部停止，`DCBSRW` 用 `.1*ACCY` 截去解析初始轨道尾部。
[START，第 195–213 行](https://github.com/compas/grasp/blob/9006157730a82ac839f2b4ff4e938bcba63a539e/src/lib/lib9290/start.f90#L195)、
[IN](https://github.com/compas/grasp/blob/9006157730a82ac839f2b4ff4e938bcba63a539e/src/appl/rmcdhf90/in.f90#L75)、
[DCBSRW，第 218–228 行](https://github.com/compas/grasp/blob/9006157730a82ac839f2b4ff4e938bcba63a539e/src/lib/lib9290/dcbsrw.f90#L218)

固定 ACCY 扫描 H 可以消除默认 H**6 的直接耦合，这是合理的。但 ACCY=1e-10
没有普适正确性；细网格也可能被同一个过松阈值限制。应在最后两个 H 上做至少一次
更严格 ACCY 的交叉检查，避免只在 D2 检查后就把 D3 也视为通过。

**确证：** 原版 SCF 先检查轨道 `SCNSTY<=ACCY`，随后又有独立条件
`abs((WTAEV−WTAEV0)/WTAEV)<.001*ACCY`，成立即设置 `CONVG=.TRUE.`。
这是“或”关系。
[SCF，第 172–228 行](https://github.com/compas/grasp/blob/9006157730a82ac839f2b4ff4e938bcba63a539e/src/appl/rmcdhf90/scf.f90#L172)

**建议：** 记录最后数轮能量与全部变分轨道 SCNSTY，区别能量停滞和轨道收敛。
ACCY=1e-12 对应能量相对阈值 1e-15，已接近双精度舍入尺度；不宜把更小阈值
自动解释成更可信结果。重体系总能量很大，能量相对变化还可能掩盖目标微小能级差。
验收应直接使用目标能级差和性质的绝对/相对预算。

**确证并纠正：** `COUNT` 确实引用 ACCY，但其判断量是两个 `SIGN(1,...)` 之和
的绝对值，对正常有限输入仅为 0 或 2。把 ACCY 从 1e-8 改到 1e-12 不会直接改变
这个符号判断；振荡振幅筛选用的是 `THRESH*EMX`。ACCY 可通过改变轨道间接影响
节点，不能笼统称为“节点筛选精度”。
[COUNT，第 51–92 行](https://github.com/compas/grasp/blob/9006157730a82ac839f2b4ff4e938bcba63a539e/src/lib/lib9290/count.f90#L51)

## 6. L 系列和巨大外端：要检查有效尾部

**确证：** `IN` 在满足尾部条件后确定 MTP，MTP 后 P/Q 清零；`QUAD` 默认表格外
尾部可忽略。因此当 MTP 远小于 N，L1/L2 可能只是延长零区。
[IN，第 141–177 行](https://github.com/compas/grasp/blob/9006157730a82ac839f2b4ff4e938bcba63a539e/src/appl/rmcdhf90/in.f90#L141)、
[QUAD，第 16–18 行](https://github.com/compas/grasp/blob/9006157730a82ac839f2b4ff4e938bcba63a539e/src/lib/lib9290/quad.f90#L16)

**建议：** L1 与 L0 一致只能说明在本次算法截断下增加数组范围无影响。完整尾部
验证还须比较更严格 ACCY 下的 `R(MTP)`、共同物理半径以外的概率和相关径向矩。
归一化会把已截掉的轨道重新归一化，因此“范数等于 1”本身不能证明尾部正确。

**源码风险及最小例程复现均已确证：** `N=2990,H=.05` 的巨大外端不仅增加开销。
`DCBSRW` 先在全部 N 点计算 RHO 多项式与 `exp(-RHO/2)*RHO**GAMMA`，然后才执行
`R>1e50` 的清零回扫。高 n 或高角动量时中间幂可能先溢出，再产生 `0*Inf`。
不能以最后会截尾为理由排除这一风险，也不能断言所有初始轨道方法都会触发。
[DCBSRW，第 194–227 行](https://github.com/compas/grasp/blob/9006157730a82ac839f2b4ff4e938bcba63a539e/src/lib/lib9290/dcbsrw.f90#L194)

本次用原版 `RADGRD+DCBSRW+CGAMMA` 等例程、仅将编译容量改为 2990/3000，
以 GNU Fortran 16.2.0 的 `-O0 -fcheck=all` 编译，设置
`C=137.035999084, ACCY=1e-10, RNT=2e-6/92, Z_eff=92, kappa=-1`，
检查 7s/8s 解析轨道表格。又以 `-O3 -fno-automatic` 编译复核，得到相同结果：

| N/H | 轨道 | 返回 MTP | 非有限值计数 | overflow / invalid |
| --- | --- | --- | --- | --- |
| 590/.05 | 7s | 379 | 0 | F/F |
| 590/.05 | 8s | 383 | 0 | F/F |
| 2990/.05 | 7s | 2656 | 6 | T/T |
| 2990/.05 | 8s | 2656 | 676 | T/T |
| 1965/.015 | 7s | 1263 | 0 | F/F |
| 1965/.015 | 8s | 1275 | 0 | F/F |

这是特定原版径向例程的真实执行结果，足以反对将 `N=2990,H=.05` 作为无须验证
的通用预填配置；它不是 U I 多电子 SCF 计算，不能外推为每种估计方法或所有
2990 容量配置都会失败。`NNNP=2990,N=1965,H=.015` 与问题组合显著不同。
非有限值计数是 P/Q 两个数组合计；两个诊断程序的退出码仍为 0。
这也直接说明退出码不能替代数值有限性检查。

**建议：** 取消脚本顶部和操作示例中 `n=2990,h=.05` 的通用预填值，要求选择
明确的试验组；容量可以继续为 2990，实际 N/H 应配套。suite 当前默认的
`FINITE_N=NNNP=2990,FINITE_H=.05` 也需要针对实际使用的初始化/求解路径复验。
本次复现使用原版例程，未冒充已经跑过 suite 的完整生产流程。

## 7. O 系列：原点尺度/网格位置敏感性，不等同于核表面加密

**公式推导：** 在固定物理半径 r，指数网格局部间距尺度为
`(r+RNT)(exp(H)−1)`。当 `r>>RNT` 时主要由 H 决定，RNT 减半几乎不改变该处
局部间距，而会平移对数网格节点位置并细化非常靠近原点的区域。
依据 [RADGRD](https://github.com/compas/grasp/blob/9006157730a82ac839f2b4ff4e938bcba63a539e/src/lib/lib9290/radgrd.f90#L48)。

以 Z=92、r=1e-4 a0 作为半径示意，`RNT=2e-6/Z` 减半后的局部间距仅减小
约 0.01087%，不是 50%。此半径示例不替代具体同位素的核分布参数。

**建议：** O 系列可保留为原点/网格位置敏感性检查；核表面分辨率要直接检查
实际核半径、Fermi 表面厚度范围内的节点间距和数量，并使用 H 扫描。比较时保持
核分布不变，不能把修改核半径后的物理变化当作网格误差。

## 8. 点核 P 系列的跨阶段缺口

**确证：** 原版 `rci90/getcid.f90` 的点核默认分支已被注释，实际始终设置
`RNT=2e-6/Z,H=.05,N=NNNP`。因此只改 `point_n/point_h/point_rnt_scale` 的 P0/P1/P2
不能保证 RCI 跟随点核专用网格；当前配置保留有限核键为 None 时，RCI 使用扩容后
的 N=990 和原有限核默认 H/RNT。核势模型是否点核和使用哪组径向网格是两回事。
[RCI GETCID，第 227–237 行](https://github.com/compas/grasp/blob/9006157730a82ac839f2b4ff4e938bcba63a539e/src/appl/rci90/getcid.f90#L227)

**建议：** 第一轮有限核生产研究可完全跳过 P 系列。若执行点核基准，先明确限制在
RMCDHF 径向求解，或另外让每个后处理入口的实际 N/H/RNT 与该点核组一致。当前
P 配置不可直接当成全流水线收敛设置。

本次实际调用补丁规划器读取三组配置，串行和 MPI RCI 均得到如下结果，
不只是依据脚本变量名推断：

| 组 | RMCDHF 的实际默认 N/H | RCI 的实际默认 N/H | RNT 系数 |
| --- | --- | --- | --- |
| P0 | 220 / .0625 | 990 / .05 | RMCDHF：exp(-65/16)；RCI：2e-6 |
| P1 | 439 / .03125 | 990 / .05 | 同上 |
| P2 | 877 / .015625 | 990 / .05 | 同上 |

一个可行的配置修正是：在点核专用副本中，将 `n/h/rnt_scale` 同时填成
对应的 `point_n/point_h/point_rnt_scale`。前一组键负责 RCI 的公共初始化，
后一组负责有点核分支的程序。例如修正后的 P1 配置建议为：

```python
GRASP_SOURCE = "."
SOURCE_LAYOUT = "grasp2018"
RUN_MODE = "preview"
PRINT_DIFF = True
GRID_PARAMETERS = {
    "nnnp": 990,
    "n": 439,  # 给原版 RCI 的公共网格初始化
    "h": 0.03125,
    "rnt_scale": 0.017205950425851383,
    "hp": 0.0,
    "accy": 1e-10,
    "point_n": 439,  # 给 RMCDHF 等程序的点核分支
    "point_h": 0.03125,
    "point_rnt_scale": 0.017205950425851383,
}
BACKUP_DIRECTORY = None
RESTORE_DIRECTORY = None
```

P0/P2 分别将两套 N/H 都改为 220/.0625、877/.015625，其他字段相同。
三组修正建议均已通过真实源码的只读修改计划检查，串行与 MPI RCI 默认值一致；
尚未编译运行其全流水线。核模型仍由 isodata 决定，这些点核专用副本不能直接
作为原有限核配置使用。990 只是本系列足以容纳 877 点的容量选择，不是精度结论。

单电子 Dirac 基准应固定点核、相同光速常数，关闭与解析参考不一致的质量修正、
Breit/QED 等项。比较最终数值能量、轨道及积分；只比较 `DCBSRW` 自己返回的
解析能量是同一公式自我核对，无法验证数值径向求解。
[DCBSRW 的解析能量计算，第 104–125 行](https://github.com/compas/grasp/blob/9006157730a82ac839f2b4ff4e938bcba63a539e/src/lib/lib9290/dcbsrw.f90#L104)
该例程返回的 E 为 `(1−EPS)*C*C`，是正的束缚能大小；与扣除静能后的负总能量
比较时，应先统一符号和能量零点。点核基准还须处于对应 Dirac 解可用的电荷范围，
例如先用 Z=1 的 1s；不能无条件套用到任意超重电荷。

## 9. 初始化和冻结轨道也属于实验条件

**确证：** `INTRPQ` 会插值并重新归一化；其 `USED` 数组容量为 NNNP，但部分
下标范围来自输入轨道点数 MA。因此不能不检查 MA 就把细网格轨道送入 590 容量
原版程序。另有 `RAMA>RN` 检查，输入轨道末点超出目标范围会停止。
[INTRPQ，第 55、75、123–148 行](https://github.com/compas/grasp/blob/9006157730a82ac839f2b4ff4e938bcba63a539e/src/lib/lib9290/intrpq.f90#L55)

**建议：** 先用各自网格上的相同估计法运行；需要共享收敛参考时，确认读入容量
足够、输入有效范围可容纳。冻结轨道插值后没有重新优化，其误差会保留；网格实验
应明确是重新执行整条逐层优化流程，还是只验证给定冻结轨道条件下的当前层。
两种实验都可以做，但所得结论覆盖范围不同。态映射应同时看 J/宇称、CI 主成分
和物理标签，不能只按能量排序对齐。

如果还要评价 `rmcdhf_orbopt` 的优化效果，应在网格研究之后单独比较：
同一候选网格上运行原版和 orbopt，再在更细网格上重复这对比较。
两种程序使用相同的核模型、CSF、ASF 权重、变分/冻结轨道列表和可比的初始轨道，
并分别报告程序退出判据及共同的外部精度验收结果。
不能把“原版 590 点且采用旧停止条件”与“orbopt 2990 点且采用严格停止条件”
之间的全部差异归于优化算法。性能比较应在达到相同目标精度及物理态后进行，
同时记录总耗时、迭代次数、每轮成本和内存，而不只比较迭代次数。

## 10. 建议的分阶段最小实验

这些是审查建议，不是新的已验证默认参数。

1. **一次性工程控制**：B0 保留原版；C0/C1 使用相同实际网格和 ACCY，确认全
   流程实际参数、边界与容量行为。普通 MPI、mem 等生产使用的变体分别确认。
2. **代表性小模型**：保留 D1/D2/D3，先固定 ACCY=1e-10 作探索；最后两个 H
   分别以更严格 ACCY 重算。若结果没有形成稳定趋势或迭代未达标，才继续细化。
3. **外端按证据触发**：先读取有效 MTP、尾部和边界余量。接近外边界或包含弥散
   态时执行 L1；已远离边界也可做一次 L1 作验证，不必默认执行 L2。
4. **按研究目标补充**：核敏感性质执行 O 检查及核表面节点检查；初始化差异用于
   排查局部解；P 系列只用于点核；MPI 缩放属于工程验证，不必每个网格全排列。
5. **生产模型复验**：最终最大活性空间比较候选及更细网格，并使用已验证的
   数值阈值。若生产流程冻结旧轨道，必须说明并验证其影响。

验收核心是同一物理态的目标量变化小于预先分配的网格误差预算，且求解残差、
尾部、插值和重复性不主导该变化。原文的 0.1 cm⁻¹、0.01 cm⁻¹、1e-3 等只能是
项目预算示例，不是 GRASP 官方精度承诺。单次相邻差很小、总能量降低、范数等于 1、
与实验吻合或补丁检查通过，均不能单独证明网格收敛。

建议对每个目标量 X 记录最后两级网格与两级 ACCY 的四个结果：

| | ACCY=t | ACCY=t/10 |
| --- | --- | --- |
| 候选网格 | X(H,t) | X(H,t/10) |
| 更细网格 | X(h,t) | X(h,t/10) |

比较同列的网格变化、同行的 ACCY 变化，以及网格差在收紧 ACCY 后是否稳定。
如果 ACCY 引起的变化已接近网格差，不能用原来固定 t 的平台宣布网格收敛。
原方案 A 系列只写在 D2 上，需要扩展到最后参与验收的另一网格；
这比机械执行全部参数组合更直接地检验误差是否混杂。

## 11. “全局生效”和现有工具的实际证据范围

**本次复核：** `test/test_patch_grasp_grid.py` 的现有 20 个测试全部通过；
原文 P0/P1/P2 的真实源码修改计划仍能成功生成，尽管它们的 RCI 网格不一致。
所以测试通过与点核流程问题并不矛盾：测试覆盖的是补丁机制和已编码的规则，
没有覆盖所有计算入口之间应满足的物理一致性。

[补丁实现](../../scripts/patch_grasp_grid.py)会同步已识别的容量定义、
修改已列出的网格初始化，并扫描 `.f90` 文件中的容量赋值和 RNT 初始化。
它不是对所有控制流和运行状态的形式证明。其证据应分层记录：

| 层次 | 可以确认的内容 | 还不能确认的内容 |
| --- | --- | --- |
| Python 配置/计划 | 参数合法、已知源码位置可以修改、重复容量定义匹配 | 所有程序按同一核模型分支解释配置 |
| 全量编译和安装 | 各目标使用新模块及库构建 | 作业实际调用了哪些二进制 |
| 作业启动与实际参数 | 程序绝对路径、输入覆盖后的 N/H/RNT/HP/ACCY | 迭代和物理量已收敛 |
| 数值和物理验收 | 有限性、态匹配、残差及目标量对网格的稳定性 | 超出已测试体系/模型的普适精度 |

还应显式记录以下入口：

- 原版交互输入可覆盖默认网格/ACCY；RCI 恢复路径从 `.res` 读取网格。
  源码设置不能覆盖掉恢复文件内的网格，网格测试应使用独立的新计算目录。
- suite 普通 MPI 版本读取 `GRASP_COUNT_ACCY` 后，在 `GETSCDmpi` 返回后直接
  覆盖共享 ACCY；该变量并非只影响 COUNT。它可能使初始化阶段与后续 SCF 使用
  不同阈值，其他程序也未必读取同一环境变量。
  依据 [orbopt_control](../../src/appl/rmcdhf90_mpi/orbopt_control.f90) 与
  [rscfmpivu](../../src/appl/rmcdhf90_mpi/rscfmpivu.f90)。
- suite 的 `GRASP_STRICT_SCF` 和轨道优化开关属于另一个算法维度。
  [普通 MPI SCF](../../src/appl/rmcdhf90_mpi/scfmpi.f90) 的严格模式需要连续满足
  轨道及能量条件；不能把此语义套在未经修改的原版或所有串行/mem 程序上。

[compare_sum.py](../../test/rmcdhf_orbopt/compare_sum.py)解析 CSF 数量、N 和能量，
不核对 H/RNT/HP/ACCY，也不检查全部变分轨道 SCNSTY。
[compare_rwfn.py](../../test/rmcdhf_orbopt/compare_rwfn.py)的梯形积分和同网格前缀
限制也不能完成本文跨网格的高精度验收。原规程已部分说明这些限制，应该保留，
并增加原版 `.sum` 末尾 Self Consistency/MTP 的明确提取与判定步骤。
固定轨道不能和本轮变分轨道混用同一个 SCNSTY 验收集合。

因此本次对话里关于“全局启用”的合理结论是：**已知源码入口的默认值可统一修改，
仍须逐阶段核验运行时值；它不是无条件覆盖一切运行路径的全局开关。**

## 附录 A：非有限值复现的独立驱动程序

在独立临时目录复制固定版本原版的以下文件；保持例程正文不变，仅在复制的
`parameter_def_M.f90` 中把 NNNP/NNN1 改为 2990/3000。本诊断没有替换或模拟
CGAMMA、RADGRD、DCBSRW 的数值实现，没有调用其他安装版本的库。
模块来自 `src/lib/libmod/`，接口和例程来自 `src/lib/lib9290/`。

保存下面代码为 `driver.f90`：

```fortran
program grid_audit
use, intrinsic :: ieee_arithmetic
use, intrinsic :: ieee_exceptions
use vast_kind_param, only: double
use parameter_def, only: nnnp
use def_c, only: c, accy, precis, expmax, expmin, pi
use grid_c, only: n, h, hp, rnt, r
use debug_c, only: ldbpr
implicit none
real(double) :: p(nnnp), q(nnnp), energy, pzero
integer :: setup, principal, mtp, nonfinite
logical :: overflowed, invalid
c=137.035999084d0
accy=1d-10
precis=epsilon(1d0)
expmax=log(huge(1d0))
expmin=log(tiny(1d0))
pi=acos(-1d0)
ldbpr=.false.
hp=0d0
rnt=2d-6/92d0
print *, 'N,H,principal,MTP,nonfinite,overflow,invalid,Rmax'
do setup=1,3
  if (setup==1) then
    n=590
    h=.05d0
  else if (setup==2) then
    n=2990
    h=.05d0
  else
    n=1965
    h=.015d0
  endif
  call radgrd
  do principal=7,8
    p=0d0
    q=0d0
    call ieee_set_flag(ieee_all,.false.)
    call dcbsrw(principal,-1,92d0,energy,pzero,p,q,mtp)
    call ieee_get_flag(ieee_overflow,overflowed)
    call ieee_get_flag(ieee_invalid,invalid)
    nonfinite=count(.not.ieee_is_finite(p(:n)))+count(.not.ieee_is_finite(q(:n)))
    print '(I0,A,F7.4,A,I0,A,I0,A,I0,A,L1,A,L1,A,ES16.8)', n,',',h,',',principal,',',mtp,',',nonfinite,',',overflowed,',',invalid,',',r(n)
  enddo
enddo
end program
```

在该临时目录按依赖顺序编译：

```sh
gfortran -O0 -fcheck=all -ffree-line-length-none \
  vast_kind_param_M.f90 parameter_def_M.f90 def_C.f90 grid_C.f90 \
  tatb_C.f90 debug_C.f90 arctan_I.f90 cgamma_I.f90 \
  arctan.f90 cgamma.f90 radgrd.f90 dcbsrw.f90 driver.f90 \
  -o grid_audit
./grid_audit
```

将 `-O0 -fcheck=all` 换成 `-O3 -fno-automatic` 可做优化构建复核。
表中的非有限值来自 `ieee_is_finite` 检查；overflow/invalid 是调用前清零、
调用后读取的 IEEE 标志。这是诊断程序，打印非有限值后仍正常退出。
其工作目录和所有编译产物均与原版及 suite 源码目录隔离。
