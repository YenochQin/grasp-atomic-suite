## S3：限定范围的双精度常量

计划基准之后，`974f0e8` 已将默认实数写成显式 `_real32` 以保持原精度。
这会消除未标 kind 的诊断，却仍保留单精度舍入后再提升的数值行为。
本次只改以下 20 个非精确字面量为 `_real64`：

| 用途 | 位置及数量 | 影响 |
| --- | --- | --- |
| SCF 收敛阈值 | 四份 `scf/scfmpi` 的 `0.001`，4 处 | 双精度计算相对能量收敛阈值；新阈值略小，临界情况下可能影响停止迭代 |
| 初始轨道 | `genrwf` 的 `0.05`；`solvh` 的 `0.1e00`、两处 `0.2e00`，4 处 | 节点/连续性阈值与能量搜索区间更新 |
| QED 积分区间 | 两份 `qed::ratden` 的 `0.0219`，2 处 | 截断网格边界的比较 |
| 矩阵求逆 | 两份 `bndinv` 的 `1.0e-8`，2 处 | 用户未给正 EPSIL 时的默认判据；显式 EPSIL 不变 |
| JJ2LSJ | `0.01`、`1.0001`、`0.00001`、`1.001`、`.998`，5 处 | 百分数提示、微小权重筛选和归一提示；不修改标签算法 |
| transition | 三份 `printaLS` 的 `0.00000001`，3 处 | 能差一致性提示，不改跃迁计算公式 |

精确的 `_real32` 字面量保留。`SLAMCH` 的单精度返回接口、未用 `cnum` 声明及
低优先级内存打印算术均未改；没有整体屏蔽诊断或批量运行自动修复。
只在整个文件已没有 real32 用途时删除其导入；JJ2LSJ/transition 的剩余用途仍有原导入。

四份 SCF 的来源链追加 [numeric-kind 快照](../reference/rmcdhf_numeric_kind_snapshot.json)，
绑定原 declarations manifest 的哈希，只覆盖四份 SCF 的前后身份。
旧快照原样保留，`check_upstream.py` 校验精确范围、前驱及最终内容。
492 份导入文件检查通过；修改本批 SCF、未改的 SOLVE 或前一 manifest 的三个篡改负例均被拒绝。

## S4：当前版本核查与实际改动

旧报告的 48 份声明顺序候选不能直接套用到当前树：`974f0e8` 已整理声明依赖并加入
`implicit none (type, external)`，`3e02e0f` 又将共享库接口迁入实现模块，删除了旧接口副本。
现有[模块化记录](library_module_migration_2026-11-16.md)说明 200 个共享过程的签名核对和回调约定。
本批不恢复已删除文件、不再重复加入 IMPLICIT NONE，也没有调整回调 ABI 或猜测 INTENT。

使用当前 Check `compile_commands.json`，为每条第一方 Fortran 编译命令增加
`-fimplicit-none -fsyntax-only`，保留其标准和宏，模块输出放入独立临时目录。
**1,956 个上下文、1,709 份源码全部通过**，不是重用旧 1,107 个上下文的结果。
没有编译上下文的未构建源码不在这项结论内。

另外落实三项小范围改动：

- 两份 `bndinv_I` 的 A/EL 原声明为 `(nsize,1)`，实现是 `(nsize,nsize)`，现已对齐。
  GNU 的过程指针关联检查不会拒绝这类显式边界差异，因此新增测试既核对两边的边界声明，
  也编译实际过程关联。此项是接口契约修正，不宣称旧正常调用已发生越界。
- JJ2LSJ 五种派生类型的 13 个指针成员添加默认 `=> null()`。
  只定义初始关联状态，保留 pointer 所有权、分配/释放路径和浅拷贝语义；不初始化局部指针以引入隐式 SAVE。
  测试覆盖新对象、动态分配的对象数组、成员分配/释放和再次构造；既有全程序转换回归也通过。
  没有将这些成员记作 13 个已复现野指针缺陷。
- `mpix_startup` 的 worker 标准输出重定向失败时，向 error_unit 报告 rank、IOSTAT、IOMSG。
  安静输出属于可选功能，失败只警告，不终止计算或插入集体等待。
  两 rank 测试覆盖安静、可见输出和打开目录的故障，均能继续通过 barrier 并正常结束。
  故障测试逐字提取生产过程，仅把硬编码文件名替换成测试路径；生产接口没有添加故障注入参数。

## 验证结果与数值对照

工具：GNU Fortran 15.3.0、Open MPI 5.0.11、Fortitude 0.10.1，Python 使用共享 Tools 环境。
本机没有规范要求的 `/usr/bin/gfortran-15`，使用已有 Homebrew GNU 15，显式设置 FC/OMPI_FC；
未修改工具链规范。Release 与 Check 都使用新构建目录。

| 验证 | 结果 |
| --- | --- |
| Release / Check 全量构建 | 两套通过 |
| Release / Check CTest | 两套各 87/87；随后登记的接口与来源链检查各 2/2，当前 89 项均已覆盖 |
| 20 个生产字面量 | 修改前 SCF 边界失败；修改后在三个缩放量级下的相邻浮点数、精确边界、典型值比较通过 |
| 两个生产 BNDINV | 修改前默认阈值边界失败；修改后边界、显式容差及普通非对角矩阵逆残差检查通过 |
| 两个完整 RATDEN 过程 | 修改前网格截断边界失败；修改后相邻、精确、旧新中点和普通网格点通过 |
| BLAS/LAPACK 接口 | 既有线性代数回归通过，含 SLAMCH 单精度返回 ABI |
| 定向 Fortitude | 12 份相关实现的 C001/C002/C021/C101/C181 检查通过；未声称全库 fortls 重扫或全库无告警 |

RATDEN 测试保留完整生产函数，只控制氢样轨道和积分过程以观察选中的网格点；
不是完整原子的 QED 自能验证。矩阵逆测试容差预先固定为机器 epsilon 的倍数，未因结果放宽。

为判断实际输出是否受影响，另运行已有小夹具。预期正常路径变化很小，但不预设逐字节不变：

- **Ni/Zn 初始轨道**：默认有限核网格，各 88 个轨道，覆盖到 n=10、l=6；比较修改前后 Release。
  两边均通过现有有限值、节点及独立归一检验，无容差变更。
  Ni 有 30 个、Zn 有 36 个轨道能量字段发生变化，最大绝对差分别为
  `1.4210854715202004e-14`、`2.1316282072803006e-14`。
  归一积分差最大分别为 `8.881784197001252e-16`、`1.1102230246251565e-15`。
  两份 RWF 二进制不相同，符合求解器浮点系数变更会传播到末位的预期；不称为物理精度提升。
- **普通 RMCDHF**：Z=10、1s² 单 CSF、有限核、590 点，H=0.05、ACCY=1.5625e-8。
  首轮的七份二进制及全部科学文本/诊断一致；再固定相同初始轨道和 MCP，设上限 30 轮对照，
  两边都实际执行 6 轮并正常结束。RWF、mix、log、sum 一致，仅忽略既有日期/时间元数据。
  本夹具未触发 SCF 新旧阈值之间的窄区间，不据此声称所有原子体系迭代次数不变。
- **memory RMCDHF 限制**：修改前后均在读取 `/proc/meminfo` 时失败，尚未进入迭代。
  本机 macOS 不提供该 Linux 文件；未伪造该文件、修改生产内存读取器或将失败计作通过。
  首轮比较脚本因此总体报告失败，普通 RMCDHF 的已完成部分仍保留。
  memory 版正常完整 SCF 对照需在支持环境补做；本批没有新增完整 MPI SCF 收敛对照。

本批支持“限定常量已用双精度计算、当前接口约束通过、现有软件回归通过”，
不支持一般原子体系的物理收敛、性能改善或所有输出完全不变的结论。
