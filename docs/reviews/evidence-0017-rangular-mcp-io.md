# 多个 J/宇称块的 MCP 容量与读写成本

2026-11-22。复核版本为 Suite `0ca7970e`，上次分析基准为 `72eaa7b0`。范围包括串行与 MPI 的角系数生成、普通 RMCDHF 的读取，以及内存版的缓存。本文给出当前版本的小样本实测和一份历史作业的容量核算。

Suite `0f35673` 已接入带目录 MPI MCP 和势系数收缩。以下旧布局、32 位统计和反复扫描的数字
属于优化前基线，保留供生产对照使用。[当前实现与本地回归](../implemented/design-0020-rmcdhf-mcp-io.md)

**在 1,401,776 个 CSF、5 个对称块、48 个 MPI 进程的历史作业中，最终 MCP 的数组主体约 312.13 GB。按现行布局，生成这些数组需要约 1.56 TB 逻辑读写。** 普通 `rmcdhf_mpi` 若读取这套数据，每次为一个轨道组装势系数，仅稀疏结构就要遍历约 315.18 GB。面向 RMCDHF 的改法是让 `rangular` 按对称块和积分组写出可定位的 MCP，让 RMCDHF 每次更新混合系数后至多为势系数读一遍相关角系数，供本轮各轨道使用。文中 GB、TB 采用十进制单位。

## 本轮修改影响了哪一段

新版 V3 描述符在 header 中记录各块的起始行和长度。Rust 读取器打开输入时顺序读取完整 Parquet 文件以核对 SHA-256，随后按 row group 定位所选块。MPI 版由 rank 0 读取，各 rank 接收本块完整的占据与耦合数组。当前主程序依次处理所有块。输入索引可以定位 CSF 数据，输出端仍按块把系数追加到各通道，RMCDHF 仍通过 Fortran 顺序记录读取它们。[描述符校验](../../src/lib/csf_descriptor/src/descriptor_reader.rs#L358) · [按块定位](../../src/lib/csf_descriptor/src/descriptor_reader.rs#L475) · [MPI 块循环](../../src/apps/rangular_mpi/rangular_mpi_main.f90#L110) · [块广播](../../src/apps/rangular_mpi/rangular_mpi_input.f90#L168)

对上述两个版本的生成、排序、稀疏结构、矩阵装配和轨道势读取路径比对，相关读写语句及其循环一致。本轮用 GNU Fortran 16.2.0 的 Release 构建复核了实际文件布局。全相互作用下，块内候选 CSF 对数为 `N_b(N_b+1)/2`，跨块无需配对。每列保留对角位置，非对角位置有保留贡献时才落盘。同一位置可以对应多个积分标签。若启用零阶／一阶分区，块内允许的相互作用会变化，估算时应使用目标作业的分区设置。[生成循环与筛选](../../src/apps/rangular_mpi/compute_mcp_angular_coefficients_mpi.f90#L115) · [MPI 分区选项](../../src/apps/rangular_mpi/read_calculation_options.f90) · [构建配置](../implemented/design-0002-fortran-build-profiles.md)

## 从贡献条数计算字节量

用 `N` 表示总 CSF 数，`E` 表示所有块、所有 rank 保存的单三角稀疏位置数，`C` 表示所有显式一电子和二电子角系数的贡献条数。同一位置可以在 `C` 中出现多次。以下取 4 字节整数、4 字节逻辑值、8 字节浮点，以及每条顺序记录首尾各 4 字节的标记。

| 数据 | 保存内容 | 主体字节 |
| --- | --- | ---: |
| 最终 `mcp.30` | 每个本地列的累计终点，每个稀疏位置的行号 | `4(N+E)` |
| 最终 `mcp.31` 和 `mcp.(32+k)` | 按积分标签分组的一电子 T 和二电子 V 系数。每条含列号、局部稀疏位置、双精度系数 | `16C` |
| MPI 临时结构通道 | 每个位置单写一条记录，含列号、行号、局部位置 | `20E`，含记录标记 |
| MPI 临时系数通道 | 每条贡献单写一条记录，含列号、局部位置、轨道标签、系数 | `28C`，含记录标记 |

MPI 按列号循环分工。每个 rank 写 `Kmax+3` 个最终文件，`Kmax` 为基组中最大的单电子 `2j`。所有块追加到这些文件。排序前要读回临时记录，并将一个 rank、一个块、一个通道的系数同时装入内存。串行版的 T/V 通道优先使用内存，缓冲不足才溢写，稀疏结构仍经临时文件。下文的临时读写量按 MPI 路径计算。[通道头](../../src/apps/rangular_mpi/connect_mcp_files.f90#L42) · [结构写出](../../src/apps/rangular_mpi/write_mcp_sparsity.f90#L85) · [整通道读回与排序](../../src/apps/rangular_mpi/sort_mcp_coefficients.f90#L92) · [串行缓冲](../../src/apps/rangular/compute_mcp_angular_coefficients.f90#L186)

可以进一步核对单个文件。设 `B` 为块数，`n,e` 为该 rank 跨块的列数和稀疏位置数，`c,g` 为该 rank、该系数通道跨块的贡献数和非空积分组数。同一标签出现在不同块或 rank 时分别计组。在上述类型宽度下，且每个逻辑记录只用一个子记录时，可以直接计算文件长度。

- 稀疏结构文件占 `99 + 51B + 4(n+e)` 字节。
- 每个系数文件占 `63 + 39B + 24g + 16c` 字节。空通道仍保存全局头、每块的头及结束记录。超大逻辑记录分成多个子记录时，还须计入附加标记。[公共头](../../src/apps/rangular_mpi/open_mcp_outputs_mpi.f90#L46) · [标签分组及结束记录](../../src/apps/rangular_mpi/sort_mcp_coefficients.f90#L223)

最终主体含 287.89 GB 系数和 24.24 GB 稀疏结构。生成端先写约 625.00 GB 临时记录，再读回同量数据，最后写出 MCP，合计约 **1.56 TB 逻辑读写**。临时文件在本块对应通道转换后删除，峰值空间取决于此前已完成的 MCP、本块尚未删除的临时通道及正在追加的输出。块 4 的 CSF 数低于块 3，临时记录却多约 7.14 GB。全作业共有 672 个最终通道文件，其中 `k=2,3,4` 三个通道贡献了 74.94% 的系数条数。

## 从 RMCDHF 的访问方式设计 MCP

以下方案按 Suite `c1377aa0` 的普通 MPI EOL（扩展最优能级）路径复核。现行 SCF 在初始化和每轮径向轨道更新结束时重新装配、对角化哈密顿量，再更新混合系数相关的权重及轨道广义占据数。在两次更新之间，拉格朗日乘子计算、普通轨道改善和失败重试都可能再次调用势系数构造。这些调用使用同一套密度权重。[SCF 调用顺序](../../src/apps/rmcdhf_mpi/run_scf_iterations_mpi.f90#L159) · [轨道对的两侧势系数](../../src/apps/rmcdhf_mpi/calculate_lagrange_multipliers_mpi.f90#L141) · [求解失败后的重试](../../src/apps/rmcdhf_mpi/improve_orbital_mpi.f90#L182)

| RMCDHF 操作 | 需要的 MCP 数据 | 对生成端布局的要求 |
| --- | --- | --- |
| 装配哈密顿量并对角化 | 对每个选根的对称块，按一电子、二电子及积分标签读取贡献，在对应稀疏位置累加当前径向积分乘以角系数 | 同一块的稀疏结构和贡献可以连续读。块目录能直接跳过未选根的块 |
| 给轨道及拉格朗日乘子构造势系数 | 对每个积分组，用当前 CSF 密度权重做收缩。凡是积分标签包含该轨道，就复用该组收缩结果，再按该轨道的广义占据数和标签位置分配到 DA、YA、XA | 每组贡献只存一份。目录保留积分标签、所含轨道和贡献所在位置，可同时服务多个轨道 |

对角化的贡献使用稀疏位置和系数来装配矩阵。势系数还需通过稀疏位置找到行 CSF，再结合列 CSF 求密度矩阵元。对一个 rank 上的积分组 `g = (对称块, T 或 V(k), 积分标签)`，可先累加 `S_g = Σ_(r,s) (2−δ_rs) D_rs A_g,rs`。这里 `D_rs` 由当前混合系数和能级权重决定，`A_g,rs` 是该组角系数。当前的一电子和二电子路径都先算这个和，再按目标轨道的广义占据数除法和轨道在标签内出现的位置处理。RMCDHF 应在每次密度权重更新后重建 `S_g`。同一轮内继续根据最新径向函数构造网格势，乘子和轨道重试可以复用已收缩的系数。角系数本身仍由 `rangular` 生成，供各次矩阵装配使用。[矩阵累加](../../src/apps/rmcdhf_mpi/assemble_hamiltonian_block.f90#L281) · [密度计算](../../src/apps/rmcdhf_mpi/csf_density_matrix_element.f90#L48) · [二电子收缩与系数分配](../../src/apps/rmcdhf_mpi/assemble_orbital_potential_coefficients.f90#L467) · [径向势与 MPI 归约](../../src/apps/rmcdhf_mpi/build_orbital_potential_mpi.f90#L37)

### rangular 写出什么

1. **按 rank 写出带目录的文件，块内保持积分分组。** 建议每个 rank 一个可按字节偏移访问的流文件。按 `块 → T、V(0)…V(Kmax) → 积分标签` 写出，块结构区保存列终点及行号。各组的目录项记录块号、通道、标签、所含轨道、偏移、长度和贡献数。生成端在现有按标签排序的写出点顺带记下目录项，每组贡献只写一份。轨道到积分组的查询可由目录生成，重复出现的同一轨道只需一条查询引用，收缩结果分配时仍按标签内的出现次数和位置处理。[现有分组写出位置](../../src/apps/rangular_mpi/sort_mcp_coefficients.f90#L223)
2. **允许矩阵装配顺读，势系数按需流读。** 求解端根据目标根寻找块位置。进入一轮势系数构造时，以全部可优化轨道和当前乘子路径涉及的轨道作为候选集合，覆盖随后才确定的追加轨道更新。按磁盘顺序读取相关积分组的并集。读入一个块的稀疏结构即可处理该块的所有通道。整块、整通道或相邻积分组可批量读，单组很大时分段读取。保留 `S_g` 或依现有运算顺序生成的 DA、YA、XA 表，下一次对角化和权重更新后使其失效。对少数目标轨道直接跳过无关数据，广泛命中时连续读可减少小请求。首版测量读取粒度和实际磁盘流量后，再决定是否做分块压缩或预读。
3. **保留可验证的数据契约。** 头部记录版本、端序、整数和浮点宽度、标签基数、基组与秩分配身份、相互作用分区。块及组的偏移、长度和计数用显式 64 位。首版可保留原贡献字段与组内次序。若按块顺读，势系数生成时仍应按原一电子块顺序及二电子的 `k → 块 → 标签` 顺序使用 `S_g`，保持浮点累加、归一化和 MPI 归约位置。对分段贡献延续同一组内累加器。通过目录跳过未选根块时，仍须处理求解器和混合系数输出所需的块状态。普通及内存版可共用读取接口，先用普通 MPI 路径对照既有格式。[无选根块分支](../../src/apps/rmcdhf_mpi/solve_hamiltonian_blocks_mpi.f90#L136) · [现有 rank 布局验证](../../src/apps/rmcdhf_mpi/connect_mcp_files.f90#L102)

### 从读盘次数估算收益

令 `M` 为一次密度权重更新到下一次更新之间实际调用势系数构造的次数，`U` 为候选轨道所涉及的积分组并集。旧路径仅结构数据就读约 `M(Kmax+2) × 4(N+E)` 字节。新路径按块只读一次相关结构，每个 `g ∈ U` 的贡献数据只读一次。某组在旧路径被访问多少次，取决于标签包含哪些轨道及这些轨道被重算的次数。旧程序已经能跳过不匹配的贡献记录，估算应按各标签组的实际访问次数计算。

若上述历史作业在一次密度更新后调用势系数构造 20 次，旧路径的结构逻辑读取约 **6.30 TB**。按块一次性收缩时，若所有块和组都需要，势系数阶段只需约 **24.24 GB 结构 + 287.89 GB 贡献主体**，另计目录和读取粒度开销。矩阵装配还需要用当前径向积分读取本阶段选定块的角系数。这里的 20 次用于说明读量如何随调用次数增长，历史日志未记录实际势系数调用次数和设备流量。

### 实施顺序

先用现有 MCP 实现 RMCDHF 的一次密度更新、一次流式收缩，作为可独立验证的改动。可按通道遍历并复用 rank 的稀疏结构，保留每组收缩结果，复用现有 DA、YA、XA 处理。随后加入 `rangular` 的块和积分组目录及配套读取接口，让相同的收缩过程只访问所需数据，同时允许按块控制结构缓存峰值。把旧路径、仅改变读取频率的路径、带目录的新文件路径分别对照，才能知道收益来自减少重算、减少读入量，还是改善读取粒度。

## 可独立实施的读写改动

### 1. 在普通 RMCDHF 中复用稀疏结构

每次为一个轨道构造势系数，一电子通道遍历一次全部块的 `.30`，随后每个二电子 `k` 重新遍历。即使该通道为空，也先读取本块行号。历史例 `Kmax=11`，共 13 遍，结构主体逻辑读取约 315.18 GB。保留 rank 本地各块结构，可复用至基组或 MPI 布局改变。若每次组装由 13 遍降为 1 遍，约少读 290.94 GB。缓存全部紧凑结构平均需 0.505 GB/rank，规划时应取最大 rank。容量受限时可考虑把块循环提到通道外层，仅保留当前块，并验证累加顺序。

系数文件中与目标轨道无关的标签组已有跳过操作，估算磁盘流量时应区分读取与跳过。内存版在启动时对整套 MCP 计数、重绕并装载，RAM 预算还须包含所有 T/V 贡献。[普通版结构循环](../../src/apps/rmcdhf_mpi/assemble_orbital_potential_coefficients.f90#L223) · [逐 k 重绕](../../src/apps/rmcdhf_mpi/assemble_orbital_potential_coefficients.f90#L368) · [内存版装载](../../src/apps/rmcdhf_mem_mpi/cache_mcp_files.f90)

矩阵装配也会重绕各 MCP 通道。在没有选取本征根的块上，普通 MPI 版仍把各组贡献读入临时标量，以便把顺序文件推进到下一块。若作业只选部分块的能级，按块记录偏移量还能省掉这部分读取。可用所有块均选根的算例和部分块选根的算例分别检验。[矩阵装配的跳块分支](../../src/apps/rmcdhf_mpi/solve_hamiltonian_blocks_mpi.f90#L138)

### 2. 减少生成端的临时记录

按列直接累积列终点及行号，若当前块能留在内存，可省去本例约 242.39 GB 的结构临时写入和读回总量（`40E`）。把多条系数装入有界缓冲并成批写出，临时系数的标记开销可减少接近 287.89 GB 的双向流量（上限 `16C`）。批量读写应保留原排序与最终文件顺序。当前排序数组每条贡献至少占 20 字节，`k=1` 另有一个整数数组。本例单个 rank、块、通道的最大计数是 33,636,293。若最重通道超过单 rank 内存预算，还需采用分段排序和归并。[临时记录](../../src/apps/rangular_mpi/compute_mcp_angular_coefficients_mpi.f90#L141) · [排序与删除](../../src/apps/rangular_mpi/compute_mcp_angular_coefficients_mpi.f90#L220) · [排序数组](../../src/apps/rangular_mpi/sort_mcp_coefficients.f90#L92)

### 3. 为永久存储缩减系数文件

每条贡献的本地位置结合 `.30` 的列终点可还原列号。省略该字段在本例可减少 71.97 GB（`4C`）。按块、通道和标签建立可寻址目录，再做分块无损压缩，可让普通读取端直接跳过无关组。现有串行样本曾将 635.79 MiB 以 Zstd 3 压至 257.53 MiB。新格式需适配串行、MPI 及各自的内存读取端，并检查解码成本、贡献顺序和浮点位模式。归档压缩率与上述节省量不能直接相加。[既有压缩测量与格式分析](evidence-0010-rangular-mpi-mcp-storage.md) · [矩阵与势系数的依赖](evidence-0011-rmcdhf-mcp-precontraction.md)

## 千万级任务的整数边界与验证
