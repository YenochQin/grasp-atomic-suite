# 风格整理第一批：关键字空格与行尾清理

日期：2026-11-17。基准为 HEAD `3e02e0f` 加当时未提交的 S1–S4 修改。
范围来自[全量工具复查](fortls_fortitude_rescan_2026-11-17.md)，按用户要求先处理风格建议。
本批只处理四条规则，不修改计算算法、字符串内容、数值常量、接口属性或可见性。

## 修改范围

| 规则 | 修改前 | 本批消除 | 剩余 |
| --- | ---: | ---: | ---: |
| S231：组合关键字缺空格 | 3,782 | 3,612 | 170 |
| S232：`go to` 等关键字空格 | 886 | 882 | 4 |

| S101：行尾空白 | 9 | 9 | 0 |
| 合计 | 4,688 | **4,514** | **174** |

共修改 **623 份 Fortran 文件**。例如 `endif` → `end if`、`elseif` → `else if`、
`enddo` → `end do`、`go to` → `goto`。不重新缩进整个文件，不统一引号，不补 END 名称，
不改数值字面量或把 USE/INTENT 建议当作纯格式修改。

剩余 174 条位于 Fortitude 报 E001、无法保证完整 AST 覆盖的文件，整份文件暂时跳过。
本轮没有运行全仓库 `--fix`；只取四条规则中标记 safe 的编辑，检查修改范围只含空白
或行尾分号，再统一写入已验证的结果。没有使用 unsafe fixes。

每份文件修改前后核对：

- 物理行数不变，没有引入新的超过 132 列的行；
- 保留字符串逐字符内容，包括转义引号和续行；
- 保留注释正文，只允许清理其行尾空白；
- 除空白及冗余行尾分号外，所有源码字符序列一致。

本次 164 份受影响的导入 RMCDHF 文件追加
[spacing 来源快照](../reference/rmcdhf_spacing_snapshot.json)，绑定上一份 numeric-kind manifest，
旧 manifest 不覆盖。`check_upstream.py` 检查前驱及修改后的精确哈希。
492 份导入文件检查通过；本批文件、未修改文件和两个历史 manifest 的篡改负例均被拒绝。

## 验证结果

GNU Fortran 15.3.0，显式设置 FC/OMPI_FC；使用独立 Release/Check 目录，Python 使用共享环境。
本机仍使用 Homebrew GNU 15，未改变仓库要求的服务器工具链约定。

- Release 和 Check 全量构建通过。
- Release 和 Check 的 CTest 分别 **89/89 通过**，包含串行/MPI、JJ2LSJ 线程、来源链及数值边界回归。
- 与本批前的独立 Release 构建比较，受影响源码对应的 **708 个编译对象全部逐字节一致**。
  多目标、串行/MPI 和线程内核重复编译会分别计数；没有当前编译对象的文本不在对象比较中。
- Fortitude 默认诊断从 **31,061 降至 26,547**，恰好减少 4,514 条。
- `C,PORT,OB,E` 加 preview 的 16,377 条诊断，按文件、规则、行号和消息比较完全一致。
  本批没有把既有 IOSTAT 风险、解析问题或科学验证限制写成已解决。

这批改动不需要新增科学计算或另设数值容差；对象字节对照与既有软件回归用于检查行为保持。
既有 macOS `/proc/meminfo` 限制及 memory 完整 SCF 对照未完成的状态仍以
[S3/S4 报告](static_numeric_interfaces_2026-11-17.md)为准。
