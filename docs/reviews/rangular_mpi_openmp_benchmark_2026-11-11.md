# rangular OpenMP MPI 和描述符输入的本机性能对照

日期：2026-11-11。源码基准：`c5f36d216f76bdd7cf9f1f762cc6ce26e3811b81`。
状态：同一 Release 构建的 33 次单机运行已完成，全部输出等价性检查通过。

在本次 14,551-CSF 样本上，8 进程 `rangular_mpi` 的整程中位数为 4.06 秒，
8 线程 `rangular_omp` 为 10.56 秒，MPI 快约 2.60 倍。
描述符使串行输入阶段从 0.222 秒降至 0.0085 秒，但整程收益只有几个百分点。
这些是当前实现、该输入和 M4 单机的结果，不代表其他基组、集群或物理收敛结论。

## 实验目的与设置

比较相同 CSF 与完整相互作用下，两种并行实现的整程耗时，以及描述符是否降低
输入和整程耗时。预期是输出保持等价、描述符主要节省解析工作；不预设并行性能排名或加速阈值。

| 项目 | 设置 |
| --- | --- |
| 输入 | 用户提供的 14,551 CSFs；4 个 block 为 1,212、3,298、4,765、5,276；17 个相对论轨道。 |
| 输入身份 | 原文本 SHA-256：`90c4949cecfa1bf0d1b3cd064a7e36f0018b56b0b1e04723e2066af1e8cb7ac9`。 |
| 硬件 | Apple M4，4 个性能核、6 个能效核，16 GiB 内存；macOS arm64。 |
| 工具链 | GNU Fortran 15.3.0，Open MPI 5.0.11，OpenBLAS；本机使用已授权的 Homebrew GNU 15。 |
| 构建 | 同一 `f2018-release` / Release / `-O2` 构建；serial、MPI、rangular OpenMP 开启，CSFG、jj2lsj OpenMP 关闭。 |
| 描述符 | 原生 rCSFs 3.0.1 生成 V2 Parquet，再由 suite 转为 `GCSDESC1` 二进制；未直接读取 Parquet。 |
| 并发 | OpenMP 1/2/4/8 线程，MPI 1/2/4/8 进程；数学库单线程；MPI 使用 `--bind-to none`，未手工绑定 CPU。 |
| OpenMP 参数 | 默认 chunk 和结果缓冲；关闭动态线程数及嵌套活跃并行层级，线程数同时通过环境和 `--threads` 指定。 |
| 重复 | 11 个组合各运行 3 次；首轮串行文本先执行，其余顺序用固定随机种子 20261111 打乱。 |

输入与可执行文件冻结为副本；各次运行使用独立目录，自动送入完整相互作用回答。
计时计算逐个执行，期间没有本任务的并行编译或测试，未清空文件缓存，也未控制系统后台负载。
异构核心由系统调度，因此线程或进程数翻倍不表示可用算力翻倍。

整程墙钟从启动进程前计至进程退出，包含 MPI launcher、初始化、计算、排序及各自格式的最终文件输出。
输入复制、描述符预处理、文件哈希和数值校验均不计入整程。
串行/OpenMP 另外启用 `--timings`；MPI 沿用现有入口，不提供同样的阶段 CSV。

## 整程计时

单位为秒；保留三轮测量，避免只展示最优值。下表中位数取未舍入的原始数据。

| 执行方式 | 第一轮 | 第二轮 | 第三轮 | 中位数 |
| --- | ---: | ---: | ---: | ---: |
| 串行，文本 | 15.283339 | 14.932117 | 14.786763 | 14.932117 |
| 串行，描述符 | 14.420758 | 15.020543 | 14.472490 | 14.472490 |
| OpenMP 1 线程，文本 | 23.204397 | 23.112666 | 23.256943 | 23.204397 |
| OpenMP 2 线程，文本 | 16.388803 | 16.323606 | 16.309521 | 16.323606 |
| OpenMP 4 线程，文本 | 12.588770 | 12.545976 | 12.468061 | 12.545976 |
| OpenMP 8 线程，文本 | 10.558890 | 10.729915 | 10.230852 | 10.558890 |
| MPI 1 进程，文本 | 17.378863 | 17.330552 | 17.523889 | 17.378863 |
| MPI 2 进程，文本 | 9.136478 | 10.335925 | 9.130910 | 9.136478 |
| MPI 4 进程，文本 | 5.588952 | 5.417856 | 5.582813 | 5.582813 |
| MPI 8 进程，文本 | 3.738862 | 4.330171 | 4.059490 | 4.059490 |
| OpenMP 8 线程，描述符 | 10.494328 | 10.266803 | 10.130328 | 10.266803 |

以普通串行文本的 14.93 秒为基准，OpenMP 8 线程加速约 1.41 倍，MPI 8 进程约 3.68 倍。
OpenMP 1、2 线程均慢于普通串行，不能只用 OpenMP 自身的 1 线程时间描述相对原程序的收益。

[OpenMP 控制器](../../src/appl/rangular/openmp/rangular_parallel.f90)按批计算 CSF 对、缓存结果并按原顺序提交，
包含结果复制和批次同步；[原 MCP 控制路径](../../src/appl/rangular/mcp_gg.f90)仍串行整理稀疏结构及排序输出。
8 线程文本输入的阶段中位数为：成对生成及缓冲 7.63 秒、排序及输出 2.34 秒、稀疏结构及输出 0.31 秒。
其中并行批次 6.40 秒是成对生成阶段的子区间，不能再次相加。

[MPI 控制路径](../../src/appl/rangular_mpi/mcpmpi_gg.f90)按列循环分配给各 rank，各自执行计算、临时 I/O、排序和输出。
它还承担 launcher、数组广播及分片 I/O 成本。上述实现差异解释了可能的开销与扩展性限制，
本次没有通过低层性能分析逐项量化它们对两者耗时差的贡献。

OpenMP 生成普通 `mcp.*`，MPI 生成 rank 分片；本实验比较各自原生输出的完成时间，
没有执行输出格式转换。后续多 rank 求解器仍须使用匹配的 MPI MCP 分片，不能直接重命名串行文件替代。

## 描述符收益与转换成本

输入阶段定义为 `input_header` 加所有 block 的 `csf_load`，包含语义验证和数组装配；
下表每项分别取三轮中位数。

| 程序 | 文本输入阶段 | 描述符输入阶段 | 文本整程 | 描述符整程 |
| --- | ---: | ---: | ---: | ---: |
| 普通串行 | 0.222342 秒 | 0.008461 秒 | 14.932117 秒 | 14.472490 秒 |
| OpenMP 8 线程 | 0.221926 秒 | 0.014258 秒 | 10.558890 秒 | 10.266803 秒 |

串行输入阶段约快 26.3 倍，但文本输入原本只占串行整程约 1.5%。
[两种加载入口](../../src/appl/rangular/rangular_input.f90)最终提供相同的 IQA/JQSA/JCUPA 数组，
不减少角系数所需的 CSF 对或改变计算内核。两种程序的整程中位数均改善约 3%，
但各自文本/描述符的三次测量范围重叠；不能把全部中位数差归因于输入优化，或承诺稳定的 3% 加速。

单次预处理实测：文本转 Parquet 约 0.032 秒、生成描述符约 0.029 秒、
描述符 Parquet 转二进制约 0.358 秒，包含导入和准备的合计约 0.738 秒。
这些是一次观测，不是三轮中位数。按需从文本转换可能抵消单次运行节省；预先生成并复用可摊薄成本。
`rangular_mpi` 尚未接入描述符输入，因此本次 MPI 组合全部使用原文本。

## 输出验证与证据

原生数组验证器确认文本与描述符的 9,239,885 个数组值完全一致。
21 次串行/OpenMP 运行的全部 10 个 MCP 文件与首轮串行文本基准逐字节一致。
每种 MPI 进程数的首轮完整分片集由 [MCP 比较器](../../scripts/mcp_compare.py)
按全局 CSF 对与串行基准比较，`atol=0, rtol=0` 时差异数均为零；
另外两轮的每个 rank 文件哈希均与对应首轮一致。因此 33 次运行均完成并通过输出验证，符合等价性预期。
本轮没有进行完整 SCF/RCI、活性空间收敛或物理精度验证。

本机原始证据保存在忽略目录 `build-benchmark-rangular/`：

- `summary.json`：源码/输入/程序身份、硬件、33 次运行、阶段计时、中位数及验证结论。
- `preparation.json`、`descriptor-verification.log`：转换成本和原生数组对照。
- `mpi-{1,2,4,8}-comparison.json`、`verification.log`：零容差 MPI 对照及完成状态。
- `prepare.py`、`benchmark.py`、`verify_results.py`：本次本机运行脚本；`runs/` 保存独立运行目录与输出。
- `configure.log`、`build.log`、`binaries/`：构建记录和实际测量程序的冻结副本。

输入数据、机器路径、二进制及完整运行产物不纳入提交。此目录不随克隆提供；
可按[输入说明](../implemented/rangular_descriptor_input.md)、[OpenMP 说明](../implemented/rangular_openmp.md)
及 [MCP 比较说明](../implemented/mcp_compare.md)，结合上述设置和原输入复测。
