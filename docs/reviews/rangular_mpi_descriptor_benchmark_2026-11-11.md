# rangular_mpi 描述符输入：实现验证与 x86 性能结果

日期：2026-11-11。源码基准：`c47f4d42b1f60bd77eb04dd3a243f545d124f481` 加本次工作树输入适配及计时增量。
实现及使用方式见 [MPI 描述符入口](../implemented/rangular_mpi_descriptor_input.md)。

**结论：本样例的 MPI 加载与广播明显变快，完整角系数计算只有小幅收益。复核三轮的输入中位耗时从 0.4111 秒降到 0.0612 秒，约快 6.72 倍；整程从 12.5652 秒降到 12.1617 秒，减少约 3.21%。全部输出与文本路径及修改前 MPI 输出一致。**

## 目的和方法

在原 MPI 进程分工和计算算法不变的前提下，检验“rank 0 从版本化二进制装配 CSF 数组并广播”是否减少输入开销，
并测量该收益在整程中的占比。预期输入阶段可加速；由于此前输入只占少量时间，不能预先承诺明显的整程加速。

本次没有用不同的计算路径作为性能对照：文本/描述符使用同一新增入口后的 Release 可执行文件，
两者都打开相同阶段计时，使用同一个 full-interaction 输入。唯一主动改变的是 CSF 输入表示。
文本路径仍调用原 CSLHMPI/LODCSLMPI，描述符由 rank 0 调用公共 reader，并广播同一组运行数组。
未变更系数计算、MPI 循环列分配、排序或输出协议。

| 条件 | 配置 |
| --- | --- |
| 硬件 | 本机 x86_64，环境报告 Ryzen 7 7800X3D，可见 8 CPU、1 NUMA 节点 |
| 工具链 | GNU Fortran 15.3.0；Open MPI 5.0.11 |
| 构建 | `f2018-release`、`-O2`；CSFG 关闭；未添加兼容性或实验优化选项 |
| MPI | 8 ranks，单机，`--bind-to none`；数学库线程固定为 1 |
| CSF 基组 | 28 电子、41 轨道、23,459 CSFs，5 blocks：1,506 / 3,933 / 5,768 / 6,276 / 5,976 |
| 科学设置 | full interaction，stdin `y` |
| 运行目录 | 短临时目录，文件系统为 tmpfs；所有计时完成后才归档完整输出 |
| 顺序 | 三轮依次：文本→描述符、描述符→文本、文本→描述符 |
| 完整墙钟 | 包括 MPI 启动/结束、计算和 MCP 输出；不包括输入复制、数组验证、输出哈希和归档 |
| 输入阶段 | rank 0 的 `input_header_and_broadcast` 加全部 `csf_load_and_broadcast`；包含广播/等待，不是纯读盘时间 |

文本 SHA-256：`7e2bf6eeec279db065bc85401c72b73f93644ffe3da3896ee3f59e417d9e63ab`。
输入二进制为已准备好的同基组 GCSDESC1 文件，3,519,366 字节；文本为 4,509,147 字节。
二进制转换成本没有包含在下列结果中。运行器先逐项验证输入数组，再开展计时，过程中没有并行执行编译或其它验证任务。

## 复核三轮结果

| 轮次 | 文本输入及广播 / 秒 | 描述符输入及广播 / 秒 | 文本整程 / 秒 | 描述符整程 / 秒 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 0.408678 | 0.052365 | 12.718475 | 11.976358 |
| 2 | 0.414032 | 0.070544 | 12.305654 | 12.250953 |
| 3 | 0.411103 | 0.061195 | 12.565240 | 12.161729 |
| 中位数 | **0.411103** | **0.061195** | **12.565240** | **12.161729** |

输入阶段中位耗时减少 **85.11%**，节省约 **0.350 秒**；整程中位耗时减少 **3.21%**，节省约 **0.404 秒**。
后者与输入节省处于同一数量级，其差额不能全归因于描述符：各 rank 的计算、排序及启动耗时仍有波动。
三轮中每一轮描述符整程均较快，但第二轮仅相差约 0.055 秒，不能据此承诺其它样例或服务器固定获得 3.21%。

从同轮文本基准看，输入阶段只占完整墙钟约 **3.27%**。
即便保持其它工作不变并把输入阶段完全消除，理论上也只能消除这约 3.27% 的时间。
因此加载阶段数倍加速和整程只有几个百分点收益是相容的。

复核之前还做过一组三轮初测：输入中位数约快 4.44 倍，整程中位耗时减少约 1.57%。
初测运行器在每轮计时结束后将完整输出从 scratch 归档到结果文件系统，可能扰动后续运行。
后将归档移至全部计时结束之后，得到上表。两组原始结果均保留，未把初测与复核混合统计。
输入加速在两组中一致出现；整程收益较小，测量幅度受系统状态影响。

此前 MPI/OpenMP 诊断中的 MPI 13.49 秒来自另一批时间采样，不应与本表描述符时间直接相除，
也不能把本表文本路径较那次更快解释为本次代码优化。这里采用同一组交替运行作为控制。

## 输出与实现验证

- 原生验证器比较全部 **14,896,465 个数组值**，头部、block 顺序以及 IQA/JQSA/JCUPA 完全一致。
- 每轮完整 **96 个 MPI MCP 文件**的文件集合及 SHA-256 均与第一轮文本一致。
- 新版文本输出另外与改造前 `c47f4d4` 的已保留 MPI 结果逐文件核对，96 个文件全部相同；因而描述符输出也与改造前相同。
- 旧 MPI 结果已在前次诊断中与普通/OpenMP 路径做过零容差比较，覆盖 38,461,197 项贡献；本次未重复进行那项耗时的语义解析，而是利用完整文件字节一致性连接到该基准。
- 新增六项 MPI 回归在 Release 和 F2018 Check 下通过，覆盖 1/2/4 ranks、空任务 rank、完整/一阶限制、相对路径、无文本文件的描述符运行、异常退出及计时防覆盖。
- F2018 矩阵维护 8 项和验收设施 7 项测试通过；没有运行全矩阵或完整物理计算。

结论只适用于本机、该基组和上述文件系统/进程配置，不代表磁盘/NFS、NUMA 多 socket、更多 MPI ranks 或更大 CSF 空间的结果。
本次没有改变内核算法或共享状态，也没有建立新的 SCF/RCI 物理精度结论。
可在实际服务器用 [MPI 对照脚本](../../scripts/compare_rangular_mpi_inputs.py) 和相同输入复核，并将 scratch 放到实际计算文件系统。
