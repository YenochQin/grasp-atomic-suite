**生产流程的计时口径。** 每套 CSF 生成一次 MCP，运行一次 RMCDHF，随后丢弃分片。作业 32 的 A 复用了已生成的分片。
将原先 A 的生成实测 10,985.87 秒和本次 C 的生成实测 10,656.03 秒，分别加上对应求解器的启动至退出墙钟，
两步合计约 8 小时 14 分和 3 小时 37 分（2.27 倍）。两步耗时取自分项测量，求解上限为一轮。完整收敛计算的总耗时仍待测。
最终 MCP 为 672 / 48 个分片，共 1.013 / 1.015 TiB，求解阶段最大单 rank 峰值 RSS 约 3.265 / 3.263 GiB（A/C）。

## 对照方法

| 对照路径 | 比较目的 |
| --- | --- |
| A．旧 MCP 与旧扫描 | 测量各阶段和各 rank 的基准读量与等待。 |
| B．旧 MCP 与一次流式收缩 | 隔离减少扫描和复用收缩的收益。 |
| C．带目录 MCP 与一次流式收缩 | 核对直接跳块、按需读取、生成成本和驻留内存。 |

A 使用 `c1377aa0`，C 使用 `0f356733` 的基准快照。B 待找回旧格式流式收缩构建后复测。A 和 B 使用相同布局的旧格式 MCP，
C 用配套的 `rangular_mpi` 重生成。固定基组、交互分区、目标根、冻结列表、初始轨道、SCF 参数、MPI 布局和
文件系统。冷、热态分别配对并检查启动前缓存。数值回归核对组收缩、矩阵、乘子、径向势、迭代能量、停止状态
及输出轨道。选用实际需要重复构造轨道势的多块算例。

记录应用层逻辑读取字节、各 rank 的实际 I/O、等待和每轮 SCF 墙钟，同时记录峰值 RSS、生成期磁盘峰值和最终文件大小。
`--mcp-trace` 记录逻辑读取量。进程 `read_bytes`、设备读量和页驻留应按各自窗口核对。性能对照关闭 `--mcp-verify`，
用独立的矩阵分段与页驻留诊断作业保存各自的采样口径。[外部采样计划](plan-0003-rmcdhf-mpi-stall-diagnostics.md)

## 本机可复核的项目

- **当前入口与数值回归。** 2026-11-26 用 GNU Fortran 16.2.1、Suite `fabca2971` 和双 rank 运行
  [MCP 路径回归](../../test/test_rmcdhf_mcp_paths.py)。5 个 CSF、两个对称块、两轮 EOL 的重复运行得到逐位相同的
  `.mix`、`.wfn` 和中间量记录。收缩通道的逻辑读量两 rank 合计 1,088 字节。内存版入口、分段组、
  空 rank／通道、64 位偏移及损坏分片检查均通过。
- **生成计时与空间。** 同日本机 Btrfs、8 ranks 复跑 Zn I AS2（79,497 个 CSF），使用此前对照中相同的
  C 版 Release 生成器和输入。输出 8 个 MCP 分片，共 4,247,092,884 字节，与历史计数完全一致。
  含启动和外层采样的耗时为 73.65 秒。各 rank 先跨块累加、再取中位数，CSF 对生成及临时记录写入为
  56.84 秒，稀疏结构写出为 0.68 秒，通道排序及写出为 10.49 秒。首项同时包含角系数计算与临时 I/O。
  按约 0.25 秒间隔采样，生成目录可见文件的已分配空间峰值为 5.57 GiB，瞬时峰值可能更高。
- **56.84 秒的构成。** 同一本机、输入、8-rank 绑定和 Release 选项下，依次运行原版、两次独立抽样和原版。
  在每个块的每个 rank 上，每 16 个连续本地 CSF 列随机选一列，每次共测 4,984 列。
  分别包围 T、V 计算例程和三处临时 `WRITE`，扣除空计时区间开销，按各块各 rank 的实际调用数加权，
  再按该次生成循环的耗时占比折算到历史中位数。T、V 计算分别约 **8.12、39.93 秒**（合计 84.5%），
  临时写入约 **5.45 秒**（9.6%），余量约 3.34 秒，包含筛选、标签和索引处理及估算误差。
  两次独立估算的写入时间分别为 5.40、5.51 秒，其中 V 系数写入平均约 4.52 秒。
  原版两次循环中位数为 55.75、54.90 秒，带探针时为 56.57、59.06 秒。四次产出的 8 个分片与此前基准逐 rank
  核对，仅忽略头尾的生成批次号，其余字节均一致。
- **本机 XFS 复测。** 在 XFS 工作盘上用相同二进制、输入、绑定、运行顺序和抽样列复跑四次。以 XFS 两次原版循环中位数
  （54.05、52.85 秒）的均值 53.45 秒为基线，角系数计算约占 45.82 秒（T 7.38、V 38.44 秒），临时写调用占
  4.56 秒（8.5%，两次估计为 4.57、4.56 秒），其余占 3.07 秒。四轮的分片按上述口径均与 Btrfs 输出一致。
  按各自两次原版对照的均值换算，工作区 Btrfs 的临时写入为 5.31 / 55.32 秒（9.6%）。
  两个工作目录位于不同 NVMe 设备，且 Btrfs 启用了压缩，差值仅适用于这两套挂载配置。

就 Zn I AS2 而言，两套本机配置下时间优化均优先分析双电子 V 角系数计算。若仅将临时写调用耗时减半，按此前 Btrfs 基线估计可省约
2.7 秒（整次生成的 3.7%），按 XFS 原版平均墙钟 69.33 秒估计可省约 2.3 秒（3.3%）。这个估算只计生成循环内的写调用。批量记录对后续读回、排序及空间的影响，
需要用配套读写原型单独测量。

本次本机回归产物、逐 rank 计时、空间采样和生成摘要分别在父工作区 `temp/tests/p5.Fz57ST/` 的
`reg-local/`、`gen/<rank>/timing.rank<rank>.csv`、`generation-space.csv` 和 `generation-summary.json`。
计时拆分的源码、两组逐列样本、原版对照及校验摘要在 `temp/tests/zn-split.cegtU5/`，汇总见 `summary.json`。
XFS 的计时、空间采样和校验摘要归档于 `temp/tests/zn-xfs-split.wMZxad/`，两处挂载的同口径比较见 `mount-comparison.json`。

## 待实施与验收

1. **服务器空闲后补齐 Cd I 重复配对。** 保留现有 A/C 分片、输入和 48-rank 布局，补做 C→A 冷态，逐组核对三个生产指标和数值输出。
   Cd I 单套分片超过该节点的物理内存，全量热态对照仅用于能核验全部页面驻留的算例。逐轮诊断和性能计时各用独立作业。
2. **核算一次生成、一次求解的资源成本。** 下次生成时采集临时文件与最终分片并存期间的已分配空间峰值、生成阶段耗时，
   并核对目标作业的内存预算。Cd I 的算例规模、MPI 布局和设备与本机 Zn I AS2 不同，需按其自身数据判断批量写入的优先级。
3. **补齐 B 和版本覆盖。** 取得可追溯的 B 构建后，在同条件下拆分 A→B 的收缩复用收益和 B→C 的目录格式增量。
   生产性能数字对应上述两个快照。其他 MPI 求解器的性能验收使用各自的历史基准，串行链另行评估。
