# jj2lsj 后处理并行与异步流水线方案

日期：2026-11-03。状态：讨论结论与待执行方案，尚未实施或测量新增方案的收益。
仓库基线：`fa21b900c92389dd8e5f5d110b6f782a495e61d0`；现有 OpenMP 转换实现来自 `3630f42`。
本次仅记录讨论，不修改计算代码、不启动新计算。

## 问题与结论

运行日志中的 `LS_number` 持续递增时，程序正在进行 jj–LS 系数转换；这一阶段已按 LS-CSF 行并行。
转换之后 CPU 使用率下降，引出了两个优化设想：给同一 block 的多个 ASF 分配核心并行处理，
以及将后续串行工作异步执行，使它与其他计算重叠。

**各 ASF 的独立后处理可以并行，跨 block 的计算与后处理也可以设计为流水线；
最终唯一标签分配存在 ASF 之间的依赖，不能让每个 ASF 独立决定最终标签。**
优先顺序应是：测清后处理耗时，改进现有排序算法，再评估按 ASF 并行和跨 block 异步重叠。
异步执行本身不减少计算量，也不能消除真实的数据依赖。

现有接口和验证结果分别见[实施说明](../implemented/jj2lsj_openmp.md)和
[Gd I 真实输入验证](../reviews/jj2lsj_gd_i_validation_2026-11-02.md)。

## 当前源码的工作顺序

以下行号对应上述基线的 [jj2lsj_code.f90](../../src/appl/jj2lsj90/jj2lsj_code.f90)，
后续定位应以例程名和逻辑为准。

1. `jj2lsj` 按同一 block 全部所选能级的 jj 系数构造 `ithresh`，再调用 `setLS` 建立 LS 基（1963–1983 行）。
2. 第一个 ASF 的处理过程中调用一次 `asf2ls`，同时转换该 block 的全部目标 ASF（2043–2048 行）。
3. `transform_ls_row` 对每个入选 jj-CSF 计算一次变换系数，将其复用于全部目标 ASF（272–279 行）。
4. 转换结束后，按 ASF 依次排序、准备主要成分和标签文本、写出常规文件（2096–2207 行）。
5. 每个 block 末尾释放其 LS 基和临时数组（2209–2213 行）；所有 block 的常规输出结束后，才调用 `uniquelsj`（2219–2223 行）。

因此，“每个 ASF 的常规标签文本生成”与“为多个 ASF 分配互不冲突的唯一标签”是两个不同步骤。
当前程序并不是每输出一个 ASF，就立即独立完成其唯一标签分配。

## 同一 block 的多个 ASF 怎样并行

### 转换阶段保留按 LS 行分工

对 LS 行 L 和目标 ASF k，转换为：

```text
c_LS(L,k) = sum_j T(L,j) * c_jj(j,k)
```

同一个 `T(L,j)` 可用于多个 k，现有实现已经共享这项计算。
将每个 ASF 交给一组核心独立转换，可能重复计算同一批角动量变换系数；若要避免重复，
则需共享或缓存变换矩阵，并承担相应存储和同步成本。
因此不宜仅为增加 ASF 级并发而拆掉现有的 LS 行并行和系数复用。

还必须保留共同的 `ithresh` 和提前停止规则：当前停止条件依赖所有所选 ASF 的累计权重。
把各 ASF 分开筛选或在各自达到阈值时独立结束，会改变原行为。
各 ASF 的最终后处理应等待该 block 的共同转换停止点确定。

### 转换后的独立后处理可以并行

| 工作 | 可行性 | 保持现有行为的条件 |
| --- | --- | --- |
| 各 ASF 的系数排序和主要成分筛选 | 可以并行 | 独立工作数组；保留同权重时的原始顺序和原阈值 |
| 各 ASF 的标签候选和输出文本准备 | 可以并行 | 格式化例程可重入；只读共享 LS 基 |
| 同一组 ASF 的最终唯一标签分配 | 需要组内协调 | 保留候选权重比较、冲突消解和重新选择次序 |
| 同一结果文件的写出 | 宜由单一写入者按序执行 | 按原 block、能级和记录顺序提交，不能任意交错写入 |

已测 Gd I 输入中，六个 block 的目标 ASF 数为 `[1, 2, 2, 2, 2, 1]`。
如果一个 ASF 对应一个后处理任务，单个 block 只有一到两个任务，不能仅靠增加核心数填满大量核心。
目标 ASF 更多的其他输入可能更适合这种粒度；目前没有相应性能证据。

当前 `weights`、`weights2`、`iw`、`leading_LS` 等工作区被各 ASF 依次复用，
`packlsCSF` 等格式化例程还有显式 `SAVE`。给外层循环加并行或任务指令并不足够：
需要独立工作区、线程安全的格式化过程，并处理模块状态及指针目标的实际共享关系。

## 唯一标签分配为何不能各自独立完成

假设 ASF A、B 的第一候选都是标签 α，权重分别为 0.70、0.80。
若独立处理，两者都可能选择 α；保证唯一性就必须统一决定谁保留 α、另一个使用哪个候选。

`uniquelsj` 会比较尚未分配 ASF 的当前候选权重，检查已占用标签；候选冲突时，
还会调整候选次序并重新参与选择（3381–3464 行）。这不等价于为每个 ASF 独立找最大分量，
也不等价于任意按线程完成顺序分配标签。

可并行准备候选，再由协调任务完成同一组 ASF 的最终分配。
不同 block 的标签工作可以作为进一步拆分的候选，但必须首先隔离当前共享状态和顺序文件读取，
保持原有分组、权重比较及输出行为。改成另一种全局匹配算法属于额外的算法变更，不能与调度改造混在一起验证。

当前唯一标签例程从已格式化的 `.lsj.lbl` 读回候选。若流水线改为直接传递内存数据，
还需核对原有文本舍入精度和同权重顺序，不能默认更高精度的内存候选与文件读回完全等价。

## 排序可能比写文件本身更值得优先优化

当前 LS 系数排序采用逐项插入的嵌套循环（2098–2127 行），
完成整个数组的排序后才按 `THRESH` 筛选打印项（2145–2153 行）。
因此，最终只输出少量主要成分，并不意味着之前的工作量小。

以 84,000 个 LS 系数为例，插入排序最坏的比较次数约为 `N(N-1)/2`，即约 35 亿次／ASF，
还可能包含数组元素移动。这是算法复杂度估计，不是该次运行的实测指令数或耗时。
当前实现也会排序零系数；打印阈值不会提前消除这部分排序工作。

优先候选是保持原同权重次序的 `O(N log N)` 排序，再比较是否还需要按 ASF 并行。
改变排序时应让范数累加仍按原 LS 顺序进行，不能因为排序重排而改变累计权重的浮点求和次序。
直接只取 top-k 或提前过滤低权重项需要额外检查输出模式和唯一标签候选是否齐全，不作为无条件等价替换。

已测 RCI-AS4 的三个标签文件合计只有 11,664 字节，字节量本身不大。
它不证明所有 I/O 都便宜：仍需区分排序、文本格式化、标准输出等待和文件系统写入，
尤其不能由“输出文件很小”推断整个后处理耗时很短。

## 异步流水线的可行结构

候选结构如下，尚未实现：

```text
block A 的并行转换完成
    ├─ 各 ASF 并行排序和准备候选
    │       → 组内唯一标签协调 → 缓冲结果 → 按序写出
    └─ 同时开始 block B 的转换
```

OpenMP tasks 可以立即执行或延迟交给线程团队执行，任务依赖用于约束必要的先后关系。
共享存储必须活到使用它的任务结束，这是上述流水线必须满足的条件。
参见 [OpenMP task 规范](https://openmp.org/spec-html/5.2/openmpse73.html)和
[任务依赖说明](https://www.openmp.org/spec-html/5.2/openmpse97.html)。

具体需要满足以下条件：

- **独立的 block 上下文。** 后台任务仍在访问 A 的 LS 基或系数时，不能释放这些数组，也不能让 B 覆盖全局 `asf_set_LS`。可保留必要数据，或先整理成独立结果缓冲；不能把指针浅拷贝当作数据隔离。
- **有界缓冲。** 限制同时保留的 block 和待写文本数量，避免后台任务跟不上时持续增长内存。
- **统一核心预算。** 总共分配 P 个核心时，转换、排序及其他后台任务共同使用这 P 个核心；不能让转换占满 P 核，再为每个 ASF 额外开 P 个线程。
- **有序提交。** 由一个写入者按原 block/ASF 顺序写记录；给写操作加锁只能避免同时写，不能自动保证记录顺序。
- **等待完成与错误传播。** 最后关闭文件前必须等待后台任务完成；任务失败必须传回协调端，不能将未完成结果标为成功。

异步只有在存在可重叠工作和可用资源时才可能缩短墙钟时间。
占满核心的转换与另一个 CPU 密集任务同时运行，也可能互相争用资源；最后一个 block 的收尾不能被后续转换掩盖。
这条后处理流水线同样不能消除程序最开始的输入与预处理成本。

## 建议的验证顺序

1. **先做同一次运行的分阶段计时。** 分开记录 CSF 读取/解析、`Jcoup`、mixing 输入、筛选和 LS 基生成、转换、每 ASF 排序、候选与文本准备、唯一标签分配、文件写入；同时记录 LS 数、ASF 数和输出字节数。
2. **单独验证排序替换。** 保持其他算法和线程数不变，对比系数、范数、同权重顺序、普通/唯一标签和各输出模式，确认排序是否确实占用显著时间。
3. **再评估 ASF 级后处理并行。** 使用独立工作区，区分一个、两个及更多目标 ASF 的输入，不从大量核心数量直接推断收益。
4. **最后评估跨 block 重叠。** 在同样总核心预算下比较同步流程和有界任务流水线，分别测总时间、峰值内存、等待时间及最后一块的收尾耗时。

正确性基线应沿用现有串行及 OpenMP 已验证结果：同一编译环境优先要求默认筛选后的带符号 LS 系数逐位相同，
保留共同提前停止点、零尾部、标签候选次序、最终唯一标签和文件记录顺序。
覆盖同权重、标签冲突、早停、多 block 和不同线程数；测试异步失败及未完成任务的收尾。
性能应在固定输入、阈值、资源和输出选项下重复计时，不能用改变计算量后的耗时宣称调度加速。

截至本次讨论，已确认的是上述源码依赖和已有转换兼容性结果。
排序、ASF 级后处理并行及异步流水线的实际收益仍待分阶段测量和独立验证。
