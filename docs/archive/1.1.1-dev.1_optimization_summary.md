## 1. Scope

`1.1.1-dev.1` focused on the MPI path of `RIS4_MPI -> RIS_CAL_MPI`, especially the one-body density kernels and the two-body specific-mass-shift kernels.

This branch continues the same optimization style used earlier for `RHFS_MPI -> HFSGG_MPI`: reject impossible or zero-contribution work before entering expensive angular-coefficient routines, reuse repeated arithmetic in hot accumulation loops, and avoid unnecessary MPI communication when only the root rank needs the final result.

The main runtime-facing code paths covered by this branch are:

- one-body density generation and readback:
  - `DENSNEW_MPI`
  - `DENSNEW_SELTZ_MPI`
  - `DENSREAD_MPI`
  - `DENSREAD_SELTZ_MPI`
- two-body SMS generation and readback:
  - `SMSNEW_MPI`
  - `SMSREAD_MPI`
- the MPI reduction and output control flow in `RIS_CAL_MPI`

## 2. Final Retained Optimizations

### 2.1 `RIS_CAL_MPI` YES2 density path now uses MPI kernels

File:

- [src/appl/ris4/ris_cal_mpi.f90](../../src/appl/ris4/ris_cal_mpi.f90)

Main retained change:

- The higher-order field-shift density path (`YES2`) now calls the MPI-aware Seltzer density routines when angular coefficients can be read or generated in parallel.
- This avoids falling back to the serial density implementation for the `YES2` branch during normal MPI execution.

Why this matters:

- The `YES2` branch can be a large part of `RIS_CAL_MPI` for cases requesting higher-order field-shift electronic factors.
- Keeping this branch in the MPI path preserves parallelism across the density work instead of serializing a major part of the calculation.

Related commit:

- `18c62fd` `Enable MPI path for RIS YES2 density work`

### 2.2 Zero-work screening in RIS MPI kernels

Files:

- [src/appl/ris4/densnew_mpi.f90](../../src/appl/ris4/densnew_mpi.f90)
- [src/appl/ris4/densnew_seltz_mpi.f90](../../src/appl/ris4/densnew_seltz_mpi.f90)
- [src/appl/ris4/smsnew_mpi.f90](../../src/appl/ris4/smsnew_mpi.f90)
- [src/appl/ris4/smsread_mpi.f90](../../src/appl/ris4/smsread_mpi.f90)

Main retained changes:

- One-body density kernels now skip CSF pairs after angular evaluation if all accumulated radial-density matrix elements are below the configured `CUTOFF`.
- Two-body SMS kernels skip coefficient records whose radial products collapse to zero before entering the eigenvector accumulation loop.
- The SMS read path applies the same radial zero screening for precomputed `.ITB` angular data.

Why this matters:

- It prevents zero matrix elements from flowing into the `NVEC` accumulation loop.
- It reduces useless multiply-add work after the expensive angular coefficient stage has already found a candidate pair.
- It keeps generated/read angular data behavior numerically unchanged while avoiding work that cannot affect the output.

Related commit:

- `0c045fb` `Skip zero-work paths in RIS MPI kernels`

### 2.3 Reuse eigenvector-pair products in SMS kernels

Files:

- [src/appl/ris4/smsnew_mpi.f90](../../src/appl/ris4/smsnew_mpi.f90)
- [src/appl/ris4/smsread_mpi.f90](../../src/appl/ris4/smsread_mpi.f90)

Main retained changes:

- For each `(IC, IR)` pair, the code now precomputes the scaled products
  `EVEC(IC+LOC) * EVEC(IR+LOC)` once per eigenvector.
- Both `SMSC1` and `SMSC2` accumulation reuse the same `EVPAIR` values.

Why this matters:

- The previous code recomputed the same eigenvector product separately for each SMS contribution.
- The optimized path removes repeated memory indexing and multiplication inside the coefficient loop.
- This is most useful when many SMS angular coefficients survive for a given CSF pair.

Related commit:

- `684f9f7` `Reduce repeated EVEC work in RIS MPI SMS kernels`

### 2.4 One-body outer-loop prefilter before `ONESCALAR`

Files:

- [src/appl/ris4/densnew_mpi.f90](../../src/appl/ris4/densnew_mpi.f90)
- [src/appl/ris4/densnew_seltz_mpi.f90](../../src/appl/ris4/densnew_seltz_mpi.f90)

Main retained changes:

- Before calling the expensive `ONESCALAR` path, the MPI density kernels now perform cheap outer-loop rejection:
  - `J` equality is still checked through `ITJPO`
  - parity equality is checked through `ISPAR`
  - occupation differences between `IC` and `IR` are scanned directly from `IQA`
- Pairs are rejected before `ONESCALAR` when the one-body scalar operator cannot connect them:
  - more than two changed occupations
  - any occupation change larger than one
  - off-diagonal coupling-only pairs with no occupation change

Why this matters:

- `ONESCALAR` performs recoupling and shell bookkeeping that is much more expensive than simple table checks.
- The prefilter removes many impossible CSF pairs at the outer loop, matching the successful pattern used earlier in `HFSGG_MPI`.
- This is the largest structural change in the latest optimization pass.

Related commit:

- `be1f544` `Optimize RIS4 MPI hot paths`

### 2.5 Two-body outer-loop prefilter before `RKCO_GG`

File:

- [src/appl/ris4/smsnew_mpi.f90](../../src/appl/ris4/smsnew_mpi.f90)

Main retained changes:

- Before calling `RKCO_GG`, `SMSNEW_MPI` now performs cheap screening:
  - `J` equality through `ITJPO`
  - parity equality through `ISPAR`
  - total occupation-difference feasibility for a two-body operator
- Pairs with odd total occupation difference, total difference greater than four, or any single-shell difference greater than two are skipped.
- After `RKCO_GG`, pairs with `NVCOEF = 0` skip the `EVPAIR` setup entirely.

Why this matters:

- `RKCO_GG` is the expensive two-body angular-coefficient generator.
- The new checks reject CSF pairs that cannot produce two-body SMS coefficients before entering that machinery.
- Avoiding `EVPAIR` setup for empty coefficient lists removes additional work on rejected pairs.

Related commit:

- `be1f544` `Optimize RIS4 MPI hot paths`

### 2.6 Root-only reduction for final RIS arrays

File:

- [src/appl/ris4/ris_cal_mpi.f90](../../src/appl/ris4/ris_cal_mpi.f90)

Main retained change:

- The final reductions for `SMSC1`, `SMSC2`, `DENS1` through `DENS7`, and `DENS1VEC` now use `GDRSUMMPI_ROOT` instead of `GDSUMMPI`.

Why this matters:

- Only rank 0 writes the final `RIS4_MPI` output after reduction.
- Non-root ranks do not need the reduced arrays.
- Root-only reduction avoids broadcasting the reduced result back to every rank and reduces MPI communication volume.

Related commit:

- `be1f544` `Optimize RIS4 MPI hot paths`

## 4. Attempts That Were Not Kept

No reverted optimization attempts are recorded in this branch summary.

The retained changes are conservative:

- early rejection uses the same selection rules already enforced deeper in the angular routines
- zero screening only skips contributions that are already below `CUTOFF` or exactly zero in radial products
- eigenvector-pair reuse preserves the original arithmetic factors
- root-only reduction is valid because only rank 0 consumes the reduced arrays

## 5. What The Branch Ultimately Improved

In final retained form, `1.1.1-dev.1` improved `RIS4_MPI` in three layers:

1. In the one-body density kernels, impossible CSF pairs are rejected before `ONESCALAR`.
2. In the two-body SMS kernels, impossible CSF pairs are rejected before `RKCO_GG`, and zero radial products are skipped before `NVEC` accumulation.
3. In `RIS_CAL_MPI`, the final array reductions now send results only to the root rank.

In short:

- fewer useless calls enter `ONESCALAR`
- fewer useless calls enter `RKCO_GG`
- fewer zero terms survive into eigenvector accumulation
- repeated `EVEC(IC)*EVEC(IR)` products are reused
- less MPI communication is used for final output-only data

## 6. Observed Performance Notes

Validated run logs from this branch showed the following improvement on the same `ris4_mpi` case reported during development:

Before the latest hot-path optimization:

- `RIS_CAL_MPI` wall time: `385 s`
- `RIS4_MPI` total wall time: `391 s`
- finish time: `2026/04/25 01:12:20.746 +0800`

After the retained hot-path optimization:

- `RIS_CAL_MPI` wall time: `293 s`
- `RIS4_MPI` total wall time: `299 s`
- finish time: `2026/04/25 09:10:44.286 +0800`

Observed improvement:

- total wall time reduced by `92 s`
- total wall time improved by about `23.5%`
- `RIS_CAL_MPI` time reduced by `92 s`, about `23.9%`

This is a meaningful speedup for the current RIS MPI workload because most of the reduction came from removing work before the expensive angular paths and accumulation loops, rather than from changing numerical kernels or output behavior.
